# ADR-006 パスワードハッシュにbcryptを採用する

## Status

Accepted

## Related Requirements

- FR-001
- NFR-SEC-001

## Context

会員登録でパスワードをpassword_hashへハッシュ化保存する（FR-001/NFR-SEC-001）。
平文・可逆暗号・高速ハッシュ（MD5/SHA単純適用）は不可。
ソルト付きの計算コストの高い一方向アルゴリズムが必要。

## Decision

パスワードはソルト付きbcrypt（適切なコストファクタ）でハッシュ化して保存する。
認証時は定数時間比較で検証する。

## Alternatives

- bcrypt（採用）
  - 実績が豊富でソルト・コスト調整を標準提供し要件に適合
- Argon2（不採用）
  - 妥当だが本PJで必須の優位差はなく候補保持のみ
- SHA-256等の単純ハッシュ（不採用）
  - 高速でブルートフォース耐性がなくNFR-SEC-001に不適

## Consequences

- メリット: レインボーテーブル/総当たり耐性を確保できる
- デメリット: 検証に計算コストが生じる
- 後続工程: 認証・登録テストでハッシュ保存と平文非保持を検証する

## AI Guardrails

- パスワードを平文・可逆暗号・単純ハッシュで保存してはならない（NFR-SEC-001）
- ログ・エラー・レスポンスへパスワードやハッシュを出力してはならない
