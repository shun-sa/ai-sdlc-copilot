# ADR-011 サーバー側入力検証とインジェクション/XSS対策方針

## Status

Accepted

## Related Requirements

- FR-001
- NFR-SEC-004
- NFR-SEC-005

## Context

入力値はサーバー側で検証する（NFR-SEC-004）。会員登録等で形式・必須・一意等の検証が必要（FR-001）。
SQLインジェクション・XSSを防止する（NFR-SEC-005）。
検証と対策の適用点・手段を全機能で統一する必要がある。

## Decision

全入力はサーバー側スキーマ検証（Pydantic）を必須境界とし、DBアクセスは
ORM/パラメータバインディングのみとする。SQL文字列連結を禁止し、出力は自動エスケープする。

## Alternatives

- サーバー側スキーマ検証＋パラメータバインディング＋出力エスケープ（採用）
  - NFR-SEC-004/005を構造的に満たす
- クライアント側検証中心（不採用）
  - 改ざん可能でサーバー側要件を満たさない
- 手動サニタイズ中心（不採用）
  - 抜け漏れが生じやすく網羅性に欠ける

## Consequences

- メリット: 検証とインジェクション対策を全機能で一貫適用できる
- デメリット: スキーマ定義とバインディング徹底の実装規律が必要
- 後続工程: 異常系・境界値・注入入力の検証テストを必須とする

## AI Guardrails

- ユーザー入力を連結した生SQLを実行してはならない（NFR-SEC-005）
- サーバー側検証を省略しクライアント側検証のみに依存してはならない（NFR-SEC-004）
