# ADR-007 注文・チケット購入の整合性と同時実行制御

## Status

Accepted

## Related Requirements

- FR-008
- FR-009
- NFR-AVL-001
- NFR-AVL-002

## Context

注文確定時の在庫減算、チケット購入時の残席減算は整合が必須で、
失敗時に不完全データを残せない（NFR-AVL-001..004, ERR-005）。
同時購入で在庫/残席が負になる競合を防ぐ必要がある。

## Decision

注文確定・チケット購入は単一DBトランザクションで実行する。
在庫/残席行は悲観ロック（SELECT ... FOR UPDATE相当）で取得し、
不足時は購入を失敗させ、例外時は全体をロールバックする。

## Alternatives

- ロックなしで読取後更新
  - 不採用: 競合で在庫/残席が負になりNFR-AVL違反
- アプリ層のみで在庫チェック
  - 不採用: 複数プロセス同時実行で不整合が残る
- トランザクション＋悲観ロック
  - 採用: 競合下でも整合を保ち不完全データを残さない

## Consequences

- メリット: 競合時も整合を維持し不整合データを残さない
- デメリット: ロックにより高競合時のスループットが低下
- 後続工程: 減算と登録は同一トランザクション、失敗時は必ずロールバック

## AI Guardrails

- 在庫/残席減算と注文/購入登録を別トランザクションに分けてはならない
- 在庫/残席確認から減算までロックなしで実行してはならない
