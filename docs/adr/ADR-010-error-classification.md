# ADR-010 エラー分類と表示・遷移方針

## Status

Accepted

## Related Requirements

- FR-008
- FR-009
- NFR-SEC-006

## Context

入力不備・在庫不足・権限不足・認証失敗・販売期間外の5分類で、定義済み表示と
遷移先を一致させる必要がある（AC-COM-006, ERR-001..005）。認証失敗は
アカウント存在可否を推測させない（NFR-SEC-006）。

## Decision

エラーを上記5分類に対応付けて扱う。入力不備は項目単位表示、在庫/期間外は
操作失敗＋理由表示、権限不足/未認証はログイン画面等へ遷移、認証失敗は汎用文言。
更新失敗時は不整合データを残さない。

## Alternatives

- 単一の汎用エラー表示
  - 不採用: 分類ごとの遷移要件（AC-COM-006）を満たせない
- 例外詳細をそのまま表示
  - 不採用: 内部情報露出・存在推測を招きSEC-006違反
- 5分類マッピング＋分類別表示/遷移
  - 採用: 要件どおりの表示・遷移を一貫適用できる

## Consequences

- メリット: 分類ごとに一貫した表示・遷移を提供
- デメリット: 分類判定ロジックの網羅維持が必要
- 後続工程: 認証失敗で存在有無を示す文言/挙動を出してはならない

## AI Guardrails

- 認証失敗時にアカウント存在可否を推測可能な文言を返してはならない
- 例外スタックや内部詳細をユーザー画面へ表示してはならない
