# ADR-010 テスト用に破棄可能なDBへ切替可能な構造とする

## Status

Accepted

## Related Requirements

- FR-008
- FR-009

## Context

在庫減算・残席減算・トランザクション整合（FR-008/FR-009/NFR-AVL）はDBを伴う検証が必要。
プロジェクト不変条件として、Production DB/Credential/Dataをテストで使用してはならず、
本番DBへ固定依存しない構造が求められる。

## Decision

DB接続を環境設定（接続文字列）で注入し、テストはDockerコンテナ等の
使い捨てDBに接続する。テスト間はスキーマ初期化/トランザクションロールバックで独立させる。
セッションストア接続情報・セッション機密（署名鍵/シークレット）も同様に設定注入で供給する。

## Alternatives

- 設定注入＋DisposableテストDB（採用）
  - 本番固定依存を排し実DB相当の整合性検証が可能
- 本番/共有DBへ接続（不採用）
  - 不変条件違反で危険かつ再現性がない
- 全DBをモック化（不採用）
  - トランザクション/整合性の実挙動を検証できない

## Consequences

- メリット: 本番非依存で整合性・DBテストを再現性高く実行できる
- デメリット: テスト実行環境にコンテナ等が必要
- 後続工程: 単体/結合テストは使い捨てDBを前提に構築する

## AI Guardrails

- Production DB/Credential/Dataをテストで使用してはならない
- DB接続先をソースへハードコードしてはならない（設定注入とする）
- セッションストア接続情報・セッション機密（署名鍵/シークレット）をコード/テストデータへハードコードしてはならない（設定注入とする）
