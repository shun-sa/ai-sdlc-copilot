# ADR-005 リソース認可を所有者スコープ強制で行う

## Status

Accepted

## Related Requirements

- FR-010
- NFR-SEC-002
- NFR-SEC-003

## Context

会員は自分自身のカート・注文・チケット・購入履歴のみ参照できる（C-AUTH-004）。
他会員データの参照・変更を禁止する（NFR-SEC-003）。
識別子直接指定による他者データ参照（IDOR）を防ぐ方針を確定する必要がある。

## Decision

保護リソースへのアクセスは、認証済みユーザーIDと対象リソースの所有者IDの一致を
サーバー側で必須検証する。不一致は操作不可として遷移/通知する（ERR-004）。

## Alternatives

- 所有者スコープをサーバー側で常時検証（採用）
  - IDORを構造的に防止しNFR-SEC-003に適合
- 画面非表示のみで制御（不採用）
  - APIへ直接アクセスされると防げず要件違反
- ロールのみで判定（不採用）
  - 同一ロール内の他者データ参照を防げない

## Consequences

- メリット: 他会員データ露出を構造的に防止できる
- デメリット: 参照系にも所有者検証を毎回実装する必要
- 後続工程: 全保護エンドポイントで所有者検証テストを必須とする

## AI Guardrails

- 所有者検証をクライアント側や画面表示制御のみで代替してはならない
- リクエスト値のユーザーIDを検証なしに信頼してはならない
