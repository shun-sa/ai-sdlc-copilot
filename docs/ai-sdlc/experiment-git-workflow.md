# 実験ブランチと結果の保存

## 方針

共通Agent・設定はmainで確定し、実験ごとにそこから専用ブランチ/作業先を作る。
実験ブランチには要件、設計、ADDR、生成アプリ、テスト、reportsの実行状態・結果・証跡を保存する。
実験終了後は保存を完了してからmainへ戻り、次の実験もmainの共通基準版から作る。
**実験後のコード・入力・結果はmainへマージしない。** 設定変更やAgent修正だけを別の共通環境更新として扱う。
この手順書は保存方針であり、Agentが無断でコミット、push、ブランチ作成、削除する許可ではない。

## Gitへ残すもの

- 実験の入力版、共通Agent基準版、実際のrun_id、生成アプリ/設定/テストの確定版。
- reports/requirementsの入力変換対応表と内容保持記録。02 ZIPのこの2ファイルも今回はGit管理できる。
- reports/sdlc、architecture、addrの進行状態・検査・実装引渡し情報。
- reports/loop-controlの修正履歴、未解決事項、検査結果。
- 単体/結合の計画・結果・coverage・JUnit、評価結果・受入実行証跡。
- reports/experiments/<run-id>のevents.sqlite3、固定artifacts、metrics.json、各export、run-context.json。

events.sqlite3が追記記録の正本であり、JSONLや要約だけで代替しない。
Gitでバイナリとして保存してよい。Git管理にしても計測用source_fingerprintはreportsと.gitを引き続き除外するため、
結果の追記・ステージだけをアプリ変更として数えない。.gitignore等の共通設定自体は実験開始前に確定する。
ファイルがGit管理対象でも自動コミットされるわけではない。内容を確認して明示的に追加・コミットする。

## 実験前

1. 受入試験対応と本設定変更を共通Agent側で確認して確定し、AGENT_BASE_SHAを記録する。
2. そこから新しい実験ブランチ/作業先を用意する。前回の開発完了ブランチから新しい実験を始めない。
3. 02の要件一式を投入して検証し、INPUT_BASE_SHAを記録する。比較対象ごとに入力内容・版を揃える。
4. 新しいrun_idを使い、他Runの工程状態・検査合格・coverage・DBを流用しない。
5. 受入試験表と準備用外部フォルダは開発中にリポジトリへ入れない。結合の外部参照も固定INITIALとの比較条件を守る。

ブランチだけを切り替えても、未追跡・ignoreされたファイル、外部評価フォルダ、DockerのDB/volume、環境変数は切り替わらない。
安全なのは実験ごとに別の作業先と専用DB/volume/ポートを用意する方法。worktreeでもGit履歴とrefsは共有する。
同じ作業先を再利用するときは、人が残留状態を確認する。Agentが一括削除やGitの強制クリーンで片付けない。

## 保存してmainへ戻る

1. 開発の終端状態を記録する。実施する場合は受入・評価も終え、summaryを更新する。未完了・欠測を成功や0として埋めない。
2. Agent、テスト、計測等の書込み処理が終わり、SQLiteの接続が閉じたことを確認する。
   未完了のjournal/WAL等があるDBを稼働中のままコピー・コミットしない。元のjournalや補助ファイルを勝手に削除しない。
3. 結果、証跡、生成ファイル、機密情報を確認し、必要な実験データを明示的にGitへ追加する。
4. 実験ブランチへコミットし、必要ならアクセス制限したリモートへ保存する。コミットID・run_id・環境設定を控える。
5. 未コミット変更と残留ファイルを確認してからmainへ戻る。実験ブランチは削除せず、mainへはマージしない。
6. 次の実験をmainの基準版から始める。途中結果を持った実験ブランチを次の出発点にしない。

確認・追加の例（実行対象の範囲は人が確認する）:

```text
git status --short --untracked-files=all
git check-ignore -v reports/experiments/<run-id>/metrics.json
git add -- reports
git diff --cached --stat
```

check-ignoreで出力がなく終了値1なら、そのパスは無視されていない。出力があれば個人のglobal ignoreや.git/info/excludeも確認する。
アプリ・要件等は実際のディレクトリを確認して別途追加する。一括git addですべてを無条件に公開しない。
Gitに既に追跡されているファイルはignore設定にかかわらず追跡される。

## 外部の受入作業先

受入の元表、case-bundle、bindings、tests、承認情報、実行用manifest、結果CSVは、実行中はリポジトリ外に置く。
reportsの自動証跡保存はmanifest/結果/evidenceの固定化であり、外部tests一式を自動でコピーする処理ではない。
**一式をGitへ残す場合は、評価後に外部作業先も別途アーカイブする。** 人が機密を確認し、
終了済みのその実験ブランチのreports/evaluation配下へZIP等の保存用コピーとして追加する。
外部作業先を移動・書換えたり、コピーした場所から凍結テストを再実行したりしない。
03の凍結manifestは元の絶対パスとハッシュに結び付くため、Gitから別パスへ復元しただけでそのまま再実行可能とは扱わない。
将来の再集計・再検証のため、元のフォルダ構成と必要環境も記録する。秘密情報は別管理し、除外したものを記録する。

## 評価データを次の開発へ漏らさない

Gitブランチはアクセス権の隔離ではない。mainへマージしなくても、同じリポジトリに評価ブランチがあれば
他のブランチの履歴・reports/artifacts・評価用ZIPを開発Agentが参照できる。
開発Agentには現在Run以外の評価ブランチ・証跡・外部試験を参照させない。
**厳密な非公開評価が必要なら、mainの必要履歴だけを取得した別リポジトリ/権限制御した実行環境をRunごとに使う。**
mainの履歴自体へ既に評価データを入れてしまった場合、mainだけ取得しても隔離できないので基準版とアクセス範囲を再確認する。
過去評価ブランチを後から同じ開発環境へfetchしない。新しいworktreeだけではこの履歴の隔離を満たさない。

## 機密と再現性

reportsには認証情報、応答本文、利用者データ等が含まれる場合がある。Git管理対象にすることは公開許可ではない。
承認済み証跡を後から黙って編集するとハッシュ検証に失敗する。必要なマスキングは保存方針を先に決めて生成時に適用する。
採取済み証跡を編集する必要が生じたら、元の測定の有効性と公開範囲を人へ返却して判断する。
DB/volumeの内容、外部サービス、依存パッケージ、ブラウザの状態はGitへ保存したソースとreportsだけでは再現されない。
実験用データ・seed・ツール版・手順を安全な範囲で記録し、復元できない状態は欠落として明示する。
