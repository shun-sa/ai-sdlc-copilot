## 3. 背景

### 3.1 判断が必要な理由

要件は平文・復号可能な形式で保持しないこと、同じパスワードの利用者どうしで保持値が異なることのみを確定し（NFR-SC-01、CMN-06）、具体方式は設計に委ねている（OQ-LDB-001）。方式は認証系 API の応答時間（NFR-PF-09）と初期データ一括投入の処理時間（NFR-PF-10）にも影響するため判断が必要。

r2 改訂の理由：r1 で採用した Django 標準の PBKDF2PasswordHasher は、パスワードの UTF-8 バイト列をそのまま HMAC-SHA256 の鍵とする。HMAC は64バイト（ブロック長）以下の鍵を 0x00 で右詰めするため、末尾に NUL（U+0000）を付け加えただけの別の文字列が、鍵が64バイト以下の範囲で同一の保持値となり照合が成立する（実測：Django 5.2.7 で「Kounyu01Pass」と「Kounyu01Pass＋NUL」が一致。Django 標準の ScryptPasswordHasher も内部で PBKDF2-HMAC-SHA256 を用いるため同様に一致）。これは FR-002 の「入力されたパスワードが登録済みのパスワードと一致する場合だけログインする」（6.2.2、6.2.4 手順5、E-002-02）に反する。要件はパスワードの文字種を英字・数字の包含だけで定め、NUL を含む文字列の受理・拒否を定めていない（NFR-SC-16、FR-001 6.1.3、FR-060 6.26.3 利用者②、FR-002 6.2.3）。実装で要件にない NUL の拒否を外した結果（Quality 指摘 QR-IMPL-R2-001）顕在化し、Implementation から ADR_REQUIRED として返された。入力規則を変えずに FR-002 の一致要件を満たす保持方式の判断が必要。

### 3.2 判断時の制約

Python 3.12・Django 5.2 LTS（NFR-EN-01、NFR-EN-09）。依存ライブラリは AGPL・ライセンス不明を使わず、サポート期限内・既知脆弱性なし（NFR-EN-12、NFR-SC-11）。パスワードの前後空白は除去しない（CMN-15）。パスワードの入力規則・入力エラーの条件を追加・変更しない（NFR-SC-16、FR-001 6.1.3、FR-060 6.26.3、FR-002 6.2.3。r2 追加）。第1期の本番投入前（NFR-MG-05）であり、移行が必要な本番の保持値は存在しない。

### 4.3 決定内容

OPT-007 を採用する（r2 改訂。r1 の OPT-001 から変更）。パスワード（照合用）は、Django の PBKDF2PasswordHasher を継承し方式名を pbkdf2_sha256_sha256hex とした独自ハッシャーで生成・照合する。ハッシャーは、受け取ったパスワード（文字列）を変換せずに UTF-8 で符号化して SHA-256 を計算し、その小文字16進64文字を PBKDF2-HMAC-SHA256 の鍵として、利用者ごとの乱数ソルト・Django 5.2 の既定の反復回数で計算する。PASSWORD_HASHERS はこのハッシャー1件だけとし、会員登録（FR-001）と初期データ一括投入（FR-060）で make_password により保持値を生成し、ログイン（FR-002）で check_password（利用者モデルの check_password を含む）により照合する。反復回数は Django 5.2 の既定値を用い、既定値より小さくしない。保持値は「方式＄反復回数＄ソルト＄ハッシュ」の Django 標準形式とする。ログインでメールアドレスに一致する利用者がいない場合も、同じハッシャーで1回の照合計算を行ってから認証失敗とし、応答時間で登録有無を推測されにくくする。NUL・制御文字を含むパスワードは、要件の入力規則を満たす限り受理・保持し、照合はハッシャーの比較結果だけで判定する（入力規則・前処理を追加しない）。

### 4.4 決定理由

OPT-007 は鍵を固定長64バイトとすることで HMAC の0埋めによる同一視を除き、SHA-256 の衝突困難性の範囲で文字列として異なるパスワードを一致と判定しない（DC-005）。入力規則に手を加えないため、要件で受理されるパスワードはすべて登録・投入・ログインでき、要件の振る舞いを変えない（DC-006）。PBKDF2-HMAC-SHA256・乱数ソルト・既定の反復回数は r1 と同じであり NFR-SC-01 の一方向性と保持値の相違を満たし（DC-001）、追加の SHA-256 1回の計算時間は反復計算に比べ無視できる（DC-002、ASM-001 は不変）。追加依存はなく（DC-003）、保持値に方式名と反復回数を含むため将来の方式変更にも追従できる（DC-004）。OPT-004 は要件にない入力エラーを追加し、OPT-005 は FR-002 の一致要件に反し、OPT-001・OPT-006 は同じ同一視が残る。OPT-002 は DC-005 を満たすが、OPT-007 が依存を増やさずに全基準を満たすため採らない。
