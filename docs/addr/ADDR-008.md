## 3. 背景

### 3.1 判断が必要な理由

IFR-001 の方式と認証方式は「設計で決定」とされ（external_interface_requirements.md 4章、IF-01-SEC-01）、業務条件（同期、10秒で打切り、模擬機能は1秒以内、自動再送なし、二重決済防止、応答検証）は確定しているが、呼出しの形・10秒の実現・応答検証の配置・差替えの境界は定まっていない。後続フェーズで連携部分だけを差し替えられること（NFR-PF-17）も方式に依存する。

### 3.2 判断時の制約

外部ネットワークに接続しない・実在の決済サービスへの接続処理を実装しない（XCN-02、XCN-03、NFR-EN-05）。Docker Compose は app・db の2サービス（Steering 3章）。送信項目は注文番号・決済金額・通貨・模擬決済指示に限り個人情報・カード情報を含めない（NFR-SC-24、NFR-LG-05）。接続先を利用者の入力で変更できない（VUL-12）。

### 4.3 決定内容

OPT-001 を採用する。

1. 境界：決済ゲートウェイの抽象境界を1つ定義する。要求は order_number（注文番号）・amount（決済金額、整数円）・currency（JPY 固定）・mock_instruction（模擬決済指示：approved または declined）の4項目に限る。応答は result・transaction_ref（取引参照番号）・decline_reason（否認理由）・processed_at（処理日時）の4項目とし、模擬機能は ADDR-007 の approved・declined を返す。
2. 実装の選択：使用する実装は設定（環境ごとの設定値でなくプログラム内の既定。ADDR-014 の設定値一覧に含めない固定値）で模擬機能に固定し、利用者の入力・要求で変えられない。模擬機能は外部へ通信せず、指示どおりの結果、承認時は MOCK-＋暗号論的乱数の英数字16文字の取引参照番号、処理日時（判定用の時刻提供点の時刻、秒単位）を1秒以内に返す。
3. 呼出しと打切り：支払の業務処理（ADDR-004 のロック内）が送信操作を別スレッドで実行し、実時間（単調増加の時計）で10秒まで待つ。10秒以内に結果が得られない場合は打ち切って連携エラーとし、後から得られた結果は破棄する。送信中の例外（接続不可）も連携エラーとする。自動再送しない。送信スレッドはデータベースに一切接続しない（読取りも行わない）。模擬機能が必要とする試験用状態（遅延秒数・応答モード：ADDR-011）と処理日時に用いる現在日時は、呼出し側（要求を処理しているスレッド・接続）が送信前に時刻提供点・試験用状態から読み取り、不変の値として送信操作へ渡す（r2 追加。テストごとにロールバックする自動テストでも未コミットの試験用状態を参照できるようにするため）。
4. 応答検証：呼出し側で IF-01-EXC-04 の全条件（result が approved・declined 以外、result・processed_at の欠落、approved で transaction_ref の欠落または MOCK-＋英数字16文字以外、declined で decline_reason の欠落）を検査し、該当すれば連携エラーとする。
5. 認証（IF-01-SEC-01）：プロセス内の呼出しで外部の通信経路がないため、連携用の認証情報を用いない。
6. 画面・API の模擬決済指示：Web API の入力項目名は mock_instruction（値は approved・declined、省略時 approved）。画面は承認・否認の選択（既定は承認）。
7. 記録：送信時と応答受信時（10秒超過・応答不正を含む）に LOG-06（要求の識別子、注文番号、決済金額、通貨、結果、取引参照番号（承認時）、所要時間）を出力し（ADDR-013）、連携エラーは LOG-02 にも出力する。

### 4.4 決定理由

OPT-001 は外部ネットワークも追加サービスも使わずに IFR-001 を実現し（DC-003）、打切りと応答検証を呼出し側に置くことで、模擬機能・将来の実決済実装のどちらの不具合でも10秒の上限と応答検証が守られる（DC-001、DC-004）。抽象境界の別実装を用意すれば実決済へ差し替えられ、注文・在庫・金額・状態遷移の処理は境界の型だけに依存する（DC-002）。模擬機能の振る舞いを境界の内側で切り替えられるため、試験用の状態（ADDR-011）を注入しやすい（DC-005）。自己 HTTP 呼出しは保護すべき内部エンドポイントを増やし、別コンテナは Steering の構成に反する。
