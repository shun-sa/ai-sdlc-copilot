## 3. 背景

### 3.1 判断が必要な理由

要件は各データの項目英名を定めるが、6種類のデータを1つの JSON にどう収めるか（トップレベル構造とキー名）、業務キーによる参照をどの項目名で書くか、日時項目で受理する表記の範囲と BOM 付き UTF-8 の可否を定めていない（FILE-001 14章 OQ-FILE-001・OQ-FILE-002）。これが決まらないと、運用者が作成する定義ファイルと読込実装（TASK-014）が一致しない。

### 3.2 判断時の制約

- 定義ファイルは JSON（UTF-8）1件で、データ間の参照は業務キー（メールアドレス、仕入先コード、分類コード、商品コード、SKU、クーポンコード）で行う（DCN-08）。
- 各データは「行の並び」として記載され、記載が無いデータは0行として扱う（FR-060 手順3）。行番号は記載順に1から付ける（FR-060 入力）。
- JSON 項目名は snake_case（Steering 5.2）。日時は ISO 8601・JST 基準（Steering 6章、NFR-EN-04）。
- UTF-8 として解釈できない場合は違反（FR-060 手順3、AC-UC-013-009）。
- 定義ファイルは外部入力であり、サーバー側で型・桁数・値域・形式を検証する（NFR-SC-04）。

### 4.3 決定内容

- 定義ファイルのトップレベルは JSON オブジェクトとする。キーと値は次のとおりとし、値はいずれも行（JSON オブジェクト）の配列とする。users（D-01 利用者、REC-002）、suppliers（D-02 仕入先、REC-003）、collections（D-03 商品分類、REC-004）、items（D-04 商品、REC-005）、stock_units（D-06 在庫単位、REC-006）、coupons（D-07 クーポン、REC-007）。
- キーが無い場合はそのデータを0行として扱う。キーの出現順は任意とし、登録順は FR-060 手順10 に従う。
- トップレベルが JSON オブジェクトでない場合、上記キーの値が配列でない場合、配列の要素がオブジェクトでない場合は、各データが行の並びとして記載されていないものとして E-060-03（FILE-ERR-003）とする。
- 上記6キー以外のキーがトップレベルに存在する場合は、無視せず E-060-03 とする（誤記のまま投入しないため）。
- 行の項目名は FILE-001 7章の項目英名を用いる。業務キーによる参照項目名を次のとおり確定する。商品分類の親分類（FLD-015）は parent_collection_code（文字列、省略時は最上位）、商品の所属分類（FLD-021）は collection_codes（分類コードの文字列配列、省略時は0件）、在庫単位の商品（FLD-024）は item_code、在庫単位の仕入先（FLD-025）は supplier_code。
- 商品分類所属（D-05）は定義ファイルに独立したキーを持たず、items の collection_codes から生成する（FILE-RULE-007）。
- 日時項目（商品の created_at、クーポンの valid_from・valid_until）は、ISO 8601 の日付と時刻の表記（YYYY-MM-DDThh:mm:ss。秒の小数部とタイムゾーンオフセットは任意、日付と時刻の区切りは T）だけを受理する。オフセットを省略した値は JST（+09:00）として解釈する。日付のみ・時刻のみ・空白区切り・エポック秒・和暦などは日時として解釈できない値（E-060-04）とする。
- 文字コードは UTF-8 とし、先頭に UTF-8 の BOM がある場合は BOM を取り除いてから解釈する（UTF-8 として解釈できるため受理する）。UTF-8 として解釈できないファイルは E-060-03 とする。
- 定義ファイルの読込は外部入力の検証として扱い、上記の構造判定を値域判定（手順5）より前に行う。
- 標準出力の件数表示は上記6種類と商品分類所属を対象とし、ファイル内の行数と一致させる（NFR-MG-02）。

### 4.4 決定理由

FR-060 手順3 は「各データが行の並びとして記載されていない場合」を明示的に違反としており、データ別のキーを持つオブジェクト（OPT-001）がこの構造をそのまま表す。データ名（User・Supplier・Collection・Item・StockUnit・Coupon）は data_requirements.md で与えられているため、キー名はその複数形を snake_case 化するだけで導け、独自の語を持ち込まない（DC-003）。参照項目名は FILE-001 が示す参照先（分類コード・商品コード・仕入先コード）に接尾辞を合わせ、親分類のみ parent_ を前置して自己参照であることを示す。日時は Steering 6章の ISO 8601・JST 基準に合わせ、受入条件の例（オフセット付き）を受理しつつ、曖昧な表記を違反として扱う。BOM は UTF-8 の一形態であり、拒否する根拠が要件に無いため受理する（DC-005）。
