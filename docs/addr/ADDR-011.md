## 3. 背景

### 3.1 判断が必要な理由

NFR-OM-06 は (1)〜(3) の状態を ENV-01 で設定・再現でき本番では設定できないことを求め、依頼の前提として自動テストを使い捨ての試験用 DB（Docker の PostgreSQL 16 等）で実行できる構造が必要だが、状態の注入方式・本番での無効化の保証方法・試験用 DB の切替方式は要件・Steering で指定されていない。

### 3.2 判断時の制約

pytest・pytest-django、Docker Compose の app・db（Steering 3章）。自動テストを1回の操作で全件実行し外部インターネットに接続しない（NFR-OM-06、NFR-EN-05）。本番環境では開発用の機能が無効（NFR-OM-17、VUL-08）。同時実行の挙動（行ロック・条件付き一意・アドバイザリロック）は PostgreSQL に依存する（ADDR-004）。

### 4.3 決定内容

OPT-001 を採用する。

1. 開発用機能フラグ：環境変数 MINICOMMERCE_DEV_FEATURES（既定 false。定義は ADDR-014）が true のときだけ、試験支援モジュールを INSTALLED_APPS に組み込み、その管理コマンドとテーブルを有効にする。本番（MINICOMMERCE_ENV=production）で解釈後の値が true の場合は設定エラーとして起動を拒否する（ADDR-014 4.3 の2・DD-002・DD-011。r3 で ADDR-014 r3 に表現を統一）。
2. 試験用状態：試験支援モジュールのテーブルに1行で保持する。項目は (1) 固定の現在日時（秒未満を含む。未設定なら実時刻）、(2) 模擬決済の遅延秒数と応答モード（normal、connection_error、invalid_result、missing_result、missing_processed_at、missing_transaction_ref、invalid_transaction_ref、missing_decline_reason）、(3) 注文確定の障害点（none、after_stock_decrement、after_order_insert）。
3. 差し替え点：共通の時刻提供点（TASK-002）、決済ゲートウェイの模擬実装（ADDR-008）、注文確定の業務処理の障害注入点（TASK-014・TASK-019）の3か所だけが、フラグ有効時に試験用状態を読む。フラグ無効時は試験用状態を参照せず、障害注入点は何もしない。障害注入点はデータ更新の例外を発生させ、注文確定は通常の障害と同じくロールバックして E-030-11 とする。読取り側の拘束（r2 追加）：試験用状態の読取りは、要求を処理しているスレッドのデータベース接続（業務処理と同じ接続）でだけ行う。模擬決済の遅延秒数・応答モードは支払の業務処理が送信前に読み取り、値として送信操作へ渡す（送信スレッドはデータベースに接続しない：ADDR-008 DD-002）。これにより、テストごとにロールバックする自動テスト（未コミットの試験用状態）でも差し替え点が同じ状態を参照する。
4. 設定手段：管理コマンド test_state（set・clear・show）を app コンテナ内で実行して ENV-01 の手動の結合テストで設定する。自動テストは同じ設定関数を pytest のフィクスチャから呼び、各テストの終了時に必ず clear する。HTTP の設定経路は作らない。複数の接続・スレッドから同時に要求する自動テスト（ADDR-004 の同時実行試験）は、試験用状態と初期データをコミットして全接続から見えるようにする方式（pytest-django の transaction=True）で実行し、終了時に clear とデータの破棄を行う（r2 追加）。
5. 時刻の扱い：判定・記録に用いる現在日時は時刻提供点からだけ取得する。10秒の打切り・処理時間の計測は実時間の単調増加の時計を用い、試験用の現在日時の影響を受けない。
6. 使い捨て試験用 DB：自動テストは pytest-django が実行ごとに作成・破棄する試験用データベース（名前は test_ で始まる）で行い、接続先は環境変数（DB_HOST・DB_PORT・DB_NAME・DB_USER・DB_PASSWORD。ADDR-014）で与える。接続先の PostgreSQL 16 は Docker Compose の db サービス、または試験専用に起動して破棄する PostgreSQL 16 コンテナを指定できる。SQLite 等の別製品では実行しない。試験設定では開発用機能フラグを true とする。
7. 1回の操作：単体・結合の自動テストは app コンテナ内の pytest の1回の実行で全件実行でき、外部インターネットへ接続しない（模擬決済はプロセス内）。

### 4.4 決定理由

OPT-001 は本番の設定でモジュール自体が組み込まれず、設定のテーブル・コマンド・参照処理がいずれも動作しないため、設定経路が構成上存在しない（DC-001）。状態をデータベースに保持するので、複数の実行単位・自動テスト・手動の結合テストで同じ状態を共有できる（DC-002）。業務処理は時刻提供点・決済ゲートウェイ・障害注入点を通すだけで試験用の分岐を持たない（DC-003）。HTTP の経路を増やさない（DC-005）。pytest-django の試験用データベースを環境変数で選んだ PostgreSQL 16 上に作成・破棄することで、本番・検証の DB を汚さず、ロックや制約の挙動も本番と同じ製品で検証できる（DC-004）。
