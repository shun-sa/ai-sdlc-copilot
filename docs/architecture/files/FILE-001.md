| --- | --- |
| 目的 | 稼働開始前のマスタ・管理者の登録、稼働後のクーポン・未登録SKUの追加、検証環境の初期化のため、利用者・仕入先・商品分類・商品（所属分類を含む）・在庫単位・クーポンを一括で登録する（FR-060） |

| 想定最大件数 | 稼働開始時 1,157行（管理者7、仕入先20、商品分類30、商品300、在庫単位800）＋商品の所属分類指定600件（NFR-PF-10、INI-01〜INI-06）。上限値の要件なし |

| 再送・再取込 | 削除指定なしの再実行は全行が業務キー重複となり E-060-05（追加なし）。削除指定ありの再実行は1回実行と同じ状態（監査ログは実行ごとに1件増）。違反修正後の再実行で重複しない（NFR-OM-13、FR-060 6.26.9） |

### 11.1 部分成功の扱い

- 全件成功のみ（行単位の部分成功は許可しない：FR-060 6.26.4 手順8〜11、NFR-OM-13）。
- 削除指定がある場合も、違反・障害時は削除を行わない（または取り消す）。監査ログの失敗記録のみ残す（CMN-21 ただし書き）。

## 12. Security / Privacy

- Data Classification: RESTRICTED（平文パスワード（FLD-002）は CLS-04 厳秘の認証情報（data_requirements.md 8.1・PI-10。論理DB設計 13章 ATTR-ENT-001-003 と同区分）。メールアドレス・氏名（FLD-001、FLD-003）は CONFIDENTIAL（CLS-03 機密）。その他の項目は論理DB設計 13章の各 Entity の区分に従う）
- Personal / Sensitive Data: 有（利用者のメールアドレス・氏名・平文パスワード）。検証用は架空の値のみ（NFR-SC-25、DCN-15、Steering 7章）
- Encryption at Rest: 本システムの範囲外（運用者が本システム外で保管：DCN-08。本番投入用の保管は NOQ-10 未決）。登録後のパスワードは平文・復号可能な形式で保持しない（NFR-SC-01）
- Encryption in Transit: N/A（サーバー上のファイルを指定し、ネットワーク転送を行わない）
- Masking / Redaction: 違反通知・成功通知・監査ログ・アプリケーションログに項目の値（パスワード・メールアドレス・氏名を含む）を出さない（FR-060 6.26.5、NFR-SC-06、CLS-04）。システム障害時のエラーログにも例外の内容に含まれる項目値・データベースの操作に渡した値を出さない（LOG-02）
- Access Control: サーバーへのログイン権限を持つ運用者のみ（NFR-SC-15）。画面・Web API からは起動・受付しない（CMN-37）
