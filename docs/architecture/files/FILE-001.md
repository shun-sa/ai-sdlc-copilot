## 3. ファイル概要

| 項目 | 内容 |
| --- | --- |
| 目的 | 稼働開始時のマスタ登録と検証環境の初期化のため、利用者・仕入先・商品分類・商品・在庫単位・クーポンを一括投入する（FR-060） |
| 方向 | INBOUND |
| 送信元 | 運用者（ACT-005）がサーバー上に配置する（EC運営担当が作成、UC-013 PRE-UC-013-003） |
| 送信先 | MiniCommerce app コンテナの初期データ一括投入コマンド（FR-060） |
| 生成契機 | 稼働開始前のマスタ登録時、検証環境の初期化時、稼働後のクーポン等の追加投入時（運用者の手動配置） |
| 生成／受信頻度 | 随時（稼働開始前1回、検証環境の初期化時、稼働後の追加投入時。1回の実行につき1件） |
| 想定最大件数 | 稼働開始時：利用者7件、仕入先20件、商品分類30件、商品300件、商品分類所属600件、在庫単位800件、クーポン0件（INI-01〜INI-07） |
| 想定最大サイズ | 要件に記載なし（上限サイズは要件・Steeringで提供されていない） |
| 保持期間 | 本システムでは保持しない。定義ファイルの保管は運用者が本システムの外で行う（DCN-08） |
| 再送・再取込 | 可。全削除指定ありの再実行は1回実行と同じ状態になる。全削除指定なしの同一ファイル再実行は業務キー重複で全件違反となり投入しない（FR-060 二重実行防止） |

## 9. 整合性・Control情報

| 項目 | ルール |
| --- | --- |
| 件数整合 | 標準出力のデータ別投入件数が定義ファイルの行数と一致すること（AC-UC-013-001、NFR-MG-02）。ヘッダ・トレーラによる件数申告は持たない |
| 金額等の集計整合 | 該当なし（本ファイルは金額の集計項目を持たない。在庫数量の合計照合は INI-06 の確認方法として実施する） |
| 一意性 | 業務キー（email、supplier_code、collection_code、item_code、sku、code）が定義ファイル内で一意。同じ親分類の中で分類名が一意。同一商品で所属分類の重複指定が無いこと。全削除指定が無い場合は登録済みデータとの重複も違反（FR-060 手順6） |
| 並び順 | 行の記載順に1から行番号を付ける（違反出力に使用）。登録順は仕入先・商品分類（親から順）・商品・商品分類所属・在庫単位・クーポン・利用者とし、定義ファイル内の記載順には依存しない（FR-060 手順10） |
| Checksum / Hash | 該当なし（ファイルのチェックサム照合は要件で指定されていない） |
| Control ID | 該当なし（ファイル単位の管理IDを持たない。実行記録は監査ログ initial_data_load で残す。CMN-24） |

## 10. 入出力・転送条件

| 項目 | 内容 |
| --- | --- |
| Transfer Method | サーバー上へのファイル配置（app コンテナから参照できる位置）。ネットワーク転送は行わない（NFR-EN-05） |
| Location / Path | コマンド引数で指定したパス。Steering 4.1 の配置はリポジトリの app/seed/、app コンテナからは seed/initial_data.json |
| 認証・認可 | サーバーへのログイン権限を持つ運用者のみが実行する。本システムの認証・権限判定の対象外（FR-060 事前条件、UC-013） |
| Polling / Event | 該当なし（常時監視は行わない。コマンド実行時に1回だけ読み込む） |
| Timeout | 該当なし（ファイル読込のタイムアウト値は要件で提供されていない） |
| Retry | 自動再実行は行わない。再実行は運用者がコマンドで行う（FR-060） |
| Atomicity | ファイル側の原子性要件は無い。DB側は削除・登録・監査ログを一括確定し、全成功か無変更のいずれかとする（CMN-21、FR-060 手順12） |
| Archive | 該当なし（本システムは定義ファイルを移動・複写・保管しない。保管は運用者が本システム外で行う。DCN-08） |
| Delete | 該当なし（本システムは定義ファイルを削除しない） |

### 11.1 部分成功の扱い

- 全件成功のみ。1件でも違反があれば削除も登録も行わない（FR-060 手順8・手順12、AC-UC-013-006、AC-UC-013-007）。
- 整合性保証方法：値域・一意性・参照整合性の判定をすべて終えてから、削除・登録・監査ログ記録を1つの単位で確定する（CMN-21）。失敗時に残すのは監査ログの失敗記録1件のみとする。

## 12. Security / Privacy

- Data Classification: CLS-03 機密（利用者のメールアドレス・氏名）および CLS-04 厳秘（平文パスワードを含む）相当として取り扱う（data_requirements.md、Steering 8.2）。
- Personal / Sensitive Data: 有り（メールアドレス・氏名・平文パスワード）。検証用の定義ファイルは架空の値のみとする（Steering 11章）。実値は本書に記載しない。
- Encryption at Rest: 本システムでは行わない。定義ファイルの保管・保護は運用者が本システム外で行う（DCN-08、NFR-SC-07）。
- Encryption in Transit: 該当なし（ネットワーク転送を行わずサーバー上に配置する。NFR-EN-05）。
- Masking / Redaction: 標準出力・標準エラー出力・アプリケーションログ・監査ログにパスワード・メールアドレス・氏名を出力しない（NFR-SC-06、CMN-25、AC-UC-013-008）。
- Access Control: サーバーへのログイン権限を持つ運用者（ACT-005）のみ。Web画面・Web API からは実行できない（CMN-37、AC-UC-013-011）。
