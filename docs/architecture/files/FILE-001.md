## 3. ファイル概要

| 項目 | 内容 |
| --- | --- |
| 目的 | 稼働開始前のマスタ登録と検証環境の初期化のため、利用者・仕入先・商品分類・商品・在庫単位・クーポンを一括登録する（FR-060） |
| 方向 | INBOUND |
| 送信元 | ACT-005 運用者（サーバー上へ配置） |
| 送信先 | MiniCommerce の初期データ一括投入コマンド（app コンテナ） |
| 生成契機 | 運用者が稼働開始前または検証環境の初期化時に定義ファイルを配置し、コマンドを実行したとき |
| 生成／受信頻度 | 随時（稼働開始日の前日の本番投入、検証環境の初期化、稼働後のクーポン追加） |
| 想定最大件数 | 稼働開始時 1,157件（利用者7、仕入先20、商品分類30、商品300、在庫単位800）、商品分類所属600件、クーポンは稼働後に年間50件（INI-01〜INI-08、NFR-PF-10） |
| 想定最大サイズ | 要件未定義（件数のみ定義。OQ-FILE-003） |
| 保持期間 | 要件未定義（定義ファイルは運用者がサーバー上で管理し、本システムは保持しない） |
| 再送・再取込 | 可。全削除指定ありは監査ログ以外を削除してから投入、指定なしは追加投入で業務キー重複を違反とする（FR-060 手順6・手順9） |

## 8. 編集・変換ルール

| Rule ID | 対象Field / Record | 条件 | 変換・編集内容 | 異常時 |
| --- | --- | --- | --- | --- |
| FILE-RULE-001 | REC-002〜REC-007 の文字列項目（FLD-011 を除く） | 常時 | 前後の空白（半角・全角スペース、タブ、改行）を除去する（CMN-15、FR-060 手順4） | 除去後の値で値域を判定し、違反は ERROR |
| FILE-RULE-002 | FLD-010 | 常時 | 全体の英字を小文字へ変換する（他のコードは大文字・小文字を変換しない） | 変換後の値で形式・一意性を判定し、違反は ERROR |
| FILE-RULE-003 | FLD-033, FLD-042, FLD-043, FLD-045, FLD-064 | 項目が省略された場合 | 既定値を設定する（表示順0、商品説明0文字、公開状態は公開、登録日時は投入時刻、最低購入金額0） | 既定値設定後に値域を判定する |
| FILE-RULE-004 | FLD-011 | 常時 | ソルト付き一方向ハッシュ値へ変換して保持し、平文は保持しない（CMN-06） | 条件違反は ERROR（E-060-04） |
| FILE-RULE-005 | FLD-032 | 常時 | 親分類の分類コードから親分類を解決し、深さ（最上位は1、それ以外は親の深さ＋1）を算出する | 深さ4以上・循環・参照先なしは ERROR（E-060-05） |
| FILE-RULE-006 | FLD-044, FLD-051, FLD-052 | 常時 | 業務キーから対象データを解決し、識別子はシステムが付与する（DCN-08） | 参照先が存在しない場合は ERROR（E-060-05） |

## 9. 整合性・Control情報

| 項目 | ルール |
| --- | --- |
| 件数整合 | 標準出力のデータ別投入件数が定義ファイルの行数と一致すること（FR-060 手順13、INI-01〜INI-06） |
| 金額等の集計整合 | 在庫数量の合計が定義ファイルの合計と一致すること（INI-06 の投入後確認） |
| 一意性 | 業務キー（メールアドレス、仕入先コード、分類コード、商品コード、SKU、クーポンコード）、同じ親分類の中の分類名、同じ商品での所属分類の重複指定。全削除指定なしの場合は登録済みデータとの重複も違反（FR-060 手順6） |
| 並び順 | 行番号は記載順に1から付与する。登録は仕入先・商品分類（親分類から順）・商品・商品分類所属・在庫単位・クーポン・利用者の順（FR-060 手順10） |
| Checksum / Hash | 該当なし（要件にファイルのハッシュ照合の定めはない） |
| Control ID | 該当なし（ヘッダ・トレーラを持たない） |

## 10. 入出力・転送条件

| 項目 | 内容 |
| --- | --- |
| Transfer Method | サーバー上へのファイル配置（app コンテナから読み取る。画面・Web API からは受け付けない。CMN-37） |
| Location / Path | コマンド引数で指定する。Steering 9章の例は app コンテナ作業ディレクトリ基準の seed/initial_data.json |
| 認証・認可 | サーバーへのログイン権限を持つ運用者（ACT-005）。本システムの認証・権限判定の対象外（FR-060 事前条件） |
| Polling / Event | 該当なし（運用者のコマンド実行時に1回読み取る） |
| Timeout | 該当なし（要件はコマンド全体の処理時間60秒以内のみ定める。NFR-PF-10） |
| Retry | 自動再試行なし。失敗時は運用者が原因を解消して再実行する |
| Atomicity | 削除・登録・監査ログは一括確定（全成功または無変更。CMN-21、FR-060 手順12）。ファイル側の原子的な差し替え手順は要件未定義（OQ-FILE-002） |
| Archive | 要件未定義（定義ファイルの退避は運用者の管理範囲） |
| Delete | 要件未定義（本システムは定義ファイルを削除しない） |

## 11. 異常・Reject処理

| Error ID | 検出条件 | 処理 | 利用者／連携先への通知 | Log / Evidence | Retry |
| --- | --- | --- | --- | --- | --- |

### 11.1 部分成功の扱い

- 全件成功のみ（違反が1件でもあれば削除も投入も行わない。FR-060 手順8・手順12）
- 整合性保証は手順9〜11の一括確定で行う。異常終了時は監査ログ以外のデータが処理前から変化しない（CMN-21 のただし書き：失敗の監査ログ1件のみ残す）

## 12. Security / Privacy

- Data Classification: CLS-04 厳秘（パスワード平文を含む）、CLS-03 機密（メールアドレス・氏名）
- Personal / Sensitive Data: 有（利用者のメールアドレス・氏名・パスワード）。検証環境・テストでは架空の値のみを用いる（DCN-15、Steering 11章）
- Encryption at Rest: 要件未定義（ファイル自体の暗号化の定めはない。OQ-FILE-002）
- Encryption in Transit: 該当なし（ネットワーク転送を伴わない）
- Masking / Redaction: 標準出力・標準エラー出力に項目の値を表示しない。監査ログにメールアドレス・パスワード・氏名を記録しない（CMN-25、NFR-SC-06）
- Access Control: サーバーへのログイン権限を持つ運用者のみ（REF-29）。画面・Web API からは参照・投入できない（CMN-37）
- Repository Handling: 本ファイルをバージョン管理の追跡対象としない（app/seed/ 配下をバージョン管理の除外設定へ記載する）。CLS-04 の平文パスワードを含むため誤コミットを防ぐ。除外設定の整備は TASK-001、手順への明記は TASK-021 が担う（NFR-SC-07、NFR-SC-25）
- Audit Log Integrity: 本ファイルの投入は監査ログへ結果を1件追記するのみとし、全削除指定でも監査ログを削除しない。監査ログの更新・削除の手段を画面・API に設けない（NFR-SC-23、CMN-21）
- Privilege: 管理者アカウント（ロール admin）は本ファイルからの投入でのみ作成し、初期パスワードに共通の既定値を用いない（NFR-SC-15、NFR-SC-16、VUL-08）
