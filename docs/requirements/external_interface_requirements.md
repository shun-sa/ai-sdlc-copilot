## 1. 本書の目的と適用範囲

### 1.1 目的

MiniCommerce（株式会社あおば雑貨（以下「当社」）の会員向け自社ECサイト）が外部と行う連携について、連携先・目的・送受信データ・方式・頻度・タイミング・エラー時の扱い・試験時の扱い・責任分界・運用の要求を定義する。本リリース（初期リリース（第1期）、稼働開始予定 2027-04-01）の外部連携は決済サービスとの1件であり、決済代行事業者が未選定のため、決済サービスを本システム内の模擬機能（模擬決済）で代替する。本書は、模擬決済が満たすべき振る舞い（模擬決済指示どおりの結果を返し、承認時は取引参照番号を返すこと（5.1.4）、1秒以内に応答すること（5.1.3、5.1.8））もあわせて定義する。

## 5. インターフェース別要件

### 5.1 IFR-001：決済要求（売上確定）

#### 5.1.1 基本情報

| 項目 | 内容 |
|---|---|
| IF ID | IFR-001 |
| IF名称 | 決済要求（売上確定） |
| 連携先ID・名称 | EXT-01：決済サービス（模擬） |
| 方向 | 双方向（MiniCommerce→決済サービス：要求、決済サービス→MiniCommerce：応答） |
| 同期・非同期 | 同期（応答を受信してから支払の処理を継続する） |
| 優先度 | 必須 |

#### 5.1.2 連携目的と業務上の位置づけ

| 項目 | 内容 |
|---|---|
| 連携目的 | 購入者が確定した注文の合計金額について決済サービスに売上確定を要求し、承認された場合に限り注文を支払済にする。否認・連携エラーの場合は注文を支払済にしない。 |
| 業務上の位置づけ（前後の業務・処理） | 前：購入者（ACT-002）が配送先を入力して注文を確定し、注文（状態：注文受付）が作成され、全明細の在庫が引き当てられている。本IF：購入者が自分の注文に対して支払（FR-031）を実行した時点で起動する。1回の要求で1注文の支払1回分を扱い、MiniCommerce が要求を送って決済の結果を応答として受け取る（支払操作の時点で結果を受け取るため、決済サービスから MiniCommerce への要求は受け付けない）。後（承認）：注文の状態を支払済とし支払日時を記録する。出荷担当（管理者として操作）が、支払済の注文を翌営業日までに出荷登録する。後（否認・連携エラー）：注文は注文受付のままとし、購入者が再度支払を実行する、または注文をキャンセルする。 |
| 連携失敗時の業務影響 | 注文が支払済にならず、出荷登録（支払済の注文に限り可能）ができないため、出荷が開始できない。注文と在庫の引当は保持されるため、注文・在庫は失われない。購入者は時間をおいて支払を再実行する必要がある。 |

#### 5.1.3 起動契機・タイミング・頻度

| ID | 起動契機 | 起動時刻・条件 | 頻度 | 完了期限 | 前提となる先行処理 | 休日・特定日の扱い |
|---|---|---|---|---|---|---|
| IF-01-TRG-01 | 利用者操作 | 購入者（ACT-002）が自分の注文（状態：注文受付）に対して支払（FR-031）を実行したとき。受付時間帯は24時間365日（本システムの計画停止を除く）。注文が存在しない場合、他の購入者の注文の場合、状態が注文受付以外の場合、模擬決済指示が承認・否認以外の場合は IFR-001 を起動しない | 随時（支払操作1回につき1回）。平均110件/日、ピーク130件/時 | 要求送信から10秒以内に応答を受信する。10秒を超えた場合はタイムアウトとして扱う（5.1.9）。模擬機能は1秒以内に応答する | 注文確定（注文が作成され、状態が注文受付であること） | 該当なし（時刻起動・定期実行ではない） |
