## 1. 本書の目的と適用範囲



### 1.1 目的

購入者（ACT-002）が、配布されたクーポン（Coupon）のコードを自分のカートに適用し、有効期間と最低購入金額の条件を満たす場合に割引額・割引後小計・送料・消費税額・合計金額の内訳を確認できるようにする。不要になったクーポンは解除できる。1つのカートに適用できるクーポンは1枚までとし、条件を満たさない場合は適用を受け付けずに理由を示す。


### 1.2 適用範囲

| 区分 | 内容 |
|---|---|
| Use Case ID | UC-005 |
| 対象ユースケース | クーポンを適用・解除する |
| 対象リリース・範囲 | MiniCommerce 初期リリース |
| 本書で定義する | Goal、Actor、Trigger、Precondition、Flow、Postcondition、Business Rule、AC |
| 本書で定義しない | 新たな実装方式の決定。受領済みのAPI・画面条件は要求根拠として維持 |

対象範囲（原資料 In Scope）：

- クーポン適用（FR-024）：コードの正規化（前後空白の除去・英字の大文字化）、形式・カート明細・併用・存在・有効期間・最低購入金額の判定、カートへの適用。
- クーポン解除（FR-025）：適用中のクーポンをカートから外す。未適用の場合は変化なしで正常終了する。
- 注文金額計算（FR-026）：割引額（定額・定率）を含む金額内訳の再計算と、適用中クーポンの条件の再判定結果（is_applicable・not_applicable_reason）の返却。
- 未ログインの利用者・管理者による適用・解除の拒否。

対象外（原資料 Out of Scope）：

- カート明細の追加・数量変更・削除の操作（UC-004）。ただし、それらの操作後に適用中クーポンの判定結果が変わることは本UCで扱う。
- 注文確定時のクーポン条件の再判定（UC-006）。
- クーポンの登録・変更・削除（FR-OUT-02。初期データ一括投入 UC-013 で登録する）。
- 複数クーポンの併用、ポイント、ギフト券、自動適用の割引キャンペーン（FR-OUT-05）。

## 3. 目的・開始条件



### 3.1 Goal

購入者（ACT-002）が、配布されたクーポン（Coupon）のコードを自分のカートに適用し、有効期間と最低購入金額の条件を満たす場合に割引額・割引後小計・送料・消費税額・合計金額の内訳を確認できるようにする。不要になったクーポンは解除できる。1つのカートに適用できるクーポンは1枚までとし、条件を満たさない場合は適用を受け付けずに理由を示す。


### 3.2 Trigger

購入者が SCR-005 カートでクーポンコードを入力して「適用」を操作したとき、または適用中クーポンの「解除」を操作したとき。API では POST /api/cart/apply-coupon、POST /api/cart/remove-coupon を受信したとき。


### 3.3 Precondition

| ID | 前提条件 | 満たさない場合の扱い |
|---|---|---|
| PRE-UC-005-001 | 購入者（ロール buyer）がログイン済みである（API は発行から24時間以内でログアウトにより無効化されていない認証トークン、画面は無操作30分以内のログインセッションを持つ）。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |
| PRE-UC-005-002 | 適用する場合、購入者の利用中（open）カートに明細が1件以上ある（UC-004）。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |
| PRE-UC-005-003 | クーポン（コード、表示名、割引方式、割引値、最低購入金額、有効開始日時、有効終了日時）は初期データ一括投入（FR-060）で登録済みである。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |

## 7. Postcondition



### 7.1 正常終了

- 適用の場合：カートに適用中のクーポンが1枚だけあり、応答の金額内訳は FR-026 の規則で算出された割引後の値である。
- 解除の場合：カートのクーポンは未適用で、割引額は0円である。
- カート明細と在庫単位の在庫数量は、適用・解除の前後で変化しない。


### 7.2 失敗終了
