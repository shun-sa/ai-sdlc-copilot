## 1. 本書の目的と適用範囲



### 1.1 目的

購入者が、出荷前（注文受付・支払済）の自分の注文を自分で取り消し、引き当てられていた在庫数量が全明細分だけ1回だけ在庫へ戻ることで、他の購入者が購入できる状態にする。


### 1.2 適用範囲

| 区分 | 内容 |
|---|---|
| Use Case ID | UC-009 |
| 対象ユースケース | 注文をキャンセルする（購入者） |
| 対象リリース・範囲 | MiniCommerce 初期リリース |
| 本書で定義する | Goal、Actor、Trigger、Precondition、Flow、Postcondition、Business Rule、AC |
| 本書で定義しない | 新たな実装方式の決定。受領済みのAPI・画面条件は要求根拠として維持 |

対象範囲（原資料 In Scope）：

- 注文詳細画面（SCR-010）の「キャンセルする」と確認ダイアログによるキャンセル（FR-034）
- 注文キャンセル API（POST /api/purchase-orders/{purchase_order_id}/cancel）によるキャンセル（FR-034）
- 状態 created→cancelled（ST-PO-03）・paid→cancelled（ST-PO-04）の遷移、キャンセル日時の記録、全明細の在庫戻し、注文状態履歴（actor_role=buyer）の記録
- キャンセルできない状態（shipped／delivered／cancelled）の拒否と、二重キャンセルの防止

対象外（原資料 Out of Scope）：

- 支払済注文の返金（EC運営担当が本システム外で5営業日以内に行う。FR-OUT-04）
- 管理者によるキャンセル（UC-012）
- 出荷後の返品（FR-OUT-04）、明細単位の部分キャンセル
- 未払い注文の自動キャンセル（FR-OUT-12）
- キャンセル完了の通知メール（FR-OUT-08）

## 3. 目的・開始条件



### 3.1 Goal

購入者が、出荷前（注文受付・支払済）の自分の注文を自分で取り消し、引き当てられていた在庫数量が全明細分だけ1回だけ在庫へ戻ることで、他の購入者が購入できる状態にする。


### 3.2 Trigger

購入者が出荷前の注文を取り消すと決め、注文詳細画面（SCR-010）で「キャンセルする」を押す。API を利用する場合は、購入者が注文キャンセル API を呼び出す。


### 3.3 Precondition

| ID | 前提条件 | 満たさない場合の扱い |
|---|---|---|
| PRE-UC-009-001 | 購入者（ロール buyer）がログイン済みで、認証トークンまたはログインセッションが有効である。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |
| PRE-UC-009-002 | 対象の注文がログイン中の購入者の注文として存在する。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |
| PRE-UC-009-003 | キャンセルを完了するには、注文の状態が注文受付（created）または支払済（paid）である。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |

## 7. Postcondition



### 7.1 正常終了

- 注文の状態が cancelled で、cancelled_at に処理時刻（+09:00 付き）が記録されている。
- 注文の全明細の数量が、それぞれの在庫単位の在庫数量へ1回だけ加算されている。
- 注文状態履歴に from_status=created または paid、to_status=cancelled、actor_role=buyer、actor_user_id＝購入者の行が1件追加されている。
- 支払済注文の場合、paid_at と決済記録（件数・result・amount・transaction_ref・processed_at）は変化していない。
- 注文詳細で can_pay=false、can_cancel=false となる。


### 7.2 失敗終了

- エラー時は、注文の状態・各日時・在庫数量・注文状態履歴・決済記録は一切変化しない。
- 同じ注文の在庫が2回以上戻されることはない。

## 9. Acceptance Criteria / 合否判定基準



### 9.1 AC-UC-009-001：注文受付の注文をキャンセルすると全明細の数量が在庫へ戻る

| 項目 | 内容 |
|---|---|
| Type | 機能 |
| 関連Requirement ID | FR-034 |
| 関連Flow | MAIN |
| 優先度 | 必須 |

#### Given

- 購入者A（buyer-a@example.com、ロール buyer）がログイン済み。
- 注文 PO-00000001：所有者 購入者A、状態 created、明細 MUG-WHT-01（税抜単価2,500円）×2 と PLATE-BLU-02（税抜単価1,850円）×3、小計10,550円、送料0円、消費税額1,055円、合計11,605円、paid_at・cancelled_at は null。
- PO-00000001 の決済記録0件、注文状態履歴1件（なし→created）。
- 在庫単位 MUG-WHT-01 の在庫数量8、PLATE-BLU-02 の在庫数量5。


#### When

- 購入者Aが PO-00000001 の注文キャンセル API を呼び出す。


#### Then

- HTTP 200。応答は注文詳細表現で、status=cancelled、cancelled_at が要求送信時刻以上・応答受信時刻以下（秒単位で判定し、ミリ秒以下は切り捨て）の +09:00 付き ISO 8601 日時、paid_at=null、can_pay=false、can_cancel=false。
- 応答の status_history は2件で、2件目が from_status=created、to_status=cancelled、actor_role=buyer。DB の当該行の actor_user_id は購入者Aの user_id。
- 在庫単位 MUG-WHT-01 の在庫数量10、PLATE-BLU-02 の在庫数量8。
- 決済記録0件のまま。注文の各金額・明細・配送先は変化しない。
