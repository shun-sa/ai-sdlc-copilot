## 1. 本書の目的と適用範囲



### 1.1 目的

管理者（EC運営担当・出荷担当）が、全購入者の注文を条件で検索して内容（購入者・明細・配送先・決済記録・状態履歴）を確認し、支払済の注文の出荷を登録（配送伝票番号を含む）、出荷済の注文の配達完了を登録することで、購入者が注文状況を画面で確認できる状態にする。


### 1.2 適用範囲

| 区分 | 内容 |
|---|---|
| Use Case ID | UC-011 |
| 対象ユースケース | 注文を確認し出荷・配達完了を登録する |
| 対象リリース・範囲 | MiniCommerce 初期リリース |
| 本書で定義する | Goal、Actor、Trigger、Precondition、Flow、Postcondition、Business Rule、AC |
| 本書で定義しない | 新たな実装方式の決定。受領済みのAPI・画面条件は要求根拠として維持 |

対象範囲（原資料 In Scope）：

- 注文一覧（管理）（SCR-102、FR-041、GET /api/admin/purchase-orders）：order_number（完全一致）、status（複数指定・OR）、ordered_from／ordered_to（JST、両端の日を含む）、buyer_email（部分一致）、page。条件間は AND。注文日時降順・1ページ20件
- 注文詳細（管理）（SCR-103、FR-042、GET /api/admin/purchase-orders/{purchase_order_id}）：購入者情報・決済記録・状態履歴（actor_user_id 付き）・can_ship／can_deliver／can_cancel
- 出荷登録（FR-043、POST /api/admin/purchase-orders/{purchase_order_id}/ship）：paid→shipped（ST-PO-05）、出荷日時・配送伝票番号（任意）の記録
- 配達完了登録（FR-044、POST /api/admin/purchase-orders/{purchase_order_id}/deliver）：shipped→delivered（ST-PO-06）、配達完了日時の記録

対象外（原資料 Out of Scope）：

- ピッキング・梱包・発送の作業、配送業者の配達完了情報の確認（本システム外。FR-OUT-07）
- 配送業者との連携、配送日時指定（FR-OUT-07）
- 部分出荷・分割配送・返品（FR-OUT-04）
- 管理者による注文のキャンセル（UC-012）
- 出荷・配達完了の通知メール（FR-OUT-08）、帳票出力（FR-OUT-15）
- 出荷登録・配達完了登録の取消（状態の逆戻りは行わない）

## 3. 目的・開始条件



### 3.1 Goal

管理者（EC運営担当・出荷担当）が、全購入者の注文を条件で検索して内容（購入者・明細・配送先・決済記録・状態履歴）を確認し、支払済の注文の出荷を登録（配送伝票番号を含む）、出荷済の注文の配達完了を登録することで、購入者が注文状況を画面で確認できる状態にする。


### 3.2 Trigger

管理者がログイン後のトップである注文一覧（管理）（SCR-102）を開く。出荷登録は支払済注文の発送作業（本システム外）を終えたとき、配達完了登録は配送業者の配達完了情報を確認したとき（本システム外）に行う。API を利用する場合は、管理者が各 API を呼び出す。


### 3.3 Precondition

| ID | 前提条件 | 満たさない場合の扱い |
|---|---|---|
| PRE-UC-011-001 | 管理者（ロール admin）がログイン済みで、認証トークンまたはログインセッションが有効である。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |
| PRE-UC-011-002 | 出荷登録の場合、対象の注文の状態が支払済（paid）であり、本システム外で発送を終えている。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |
| PRE-UC-011-003 | 配達完了登録の場合、対象の注文の状態が出荷済（shipped）であり、本システム外で配達完了を確認している。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |

## 7. Postcondition



### 7.1 正常終了

- 検索・照会では、条件を満たす全購入者の注文と、その詳細（購入者情報・決済記録・状態履歴）を管理者が確認できている（データは変化しない）。
- 出荷登録後：状態 shipped、shipped_at に処理時刻、tracking_number に入力値（省略時 null）が記録され、注文状態履歴に paid→shipped（actor_role=admin、actor_user_id＝管理者）が1件追加されている。
- 配達完了登録後：状態 delivered、delivered_at に処理時刻が記録され、注文状態履歴に shipped→delivered（actor_role=admin）が1件追加されている。
- 出荷登録・配達完了登録の前後で在庫数量・決済記録・金額・明細・配送先は変化していない。
- 購入者の注文詳細（SCR-010）に新しい状態・日時・配送伝票番号が表示される。


### 7.2 失敗終了
