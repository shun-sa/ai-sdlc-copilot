## 1. 本書の目的と適用範囲



### 1.1 目的

管理者（EC運営担当・出荷担当）が、全購入者の注文を条件で検索して内容（購入者・明細・配送先・決済記録・状態履歴）を確認し、支払済の注文の出荷を登録（配送伝票番号を含む）、出荷済の注文の配達完了を登録することで、購入者が注文状況を画面で確認できる状態にする。


### 1.2 適用範囲

| 区分 | 内容 |
|---|---|
| Use Case ID | UC-011 |
| 対象ユースケース | 注文を確認し出荷・配達完了を登録する |
| 対象リリース・範囲 | MiniCommerce 初期リリース |
| 本書で定義する | Goal、Actor、Trigger、Precondition、Flow、Postcondition、Business Rule、AC |
| 本書で定義しない | 実装方式、画面デザイン詳細、物理データ構造、API・ファイルの物理仕様 |

対象範囲：

- 注文一覧（管理）（SCR-102、FR-041）：注文番号（完全一致）、注文状態（複数指定・いずれかに一致）、注文日の期間（日本時間、開始日・終了日を含む）、購入者のメールアドレス（部分一致）による検索とページ移動。条件間はすべてを満たすもの（「かつ」で組み合わせる）。注文日時の新しい順・1ページ20件
- 注文詳細（管理）（SCR-103、FR-042）：購入者情報・決済記録・状態履歴（実行した利用者の利用者ID付き）と、出荷登録・配達完了登録・キャンセルの可否
- 出荷登録（FR-043）：支払済→出荷済（ST-PO-05）、出荷日時・配送伝票番号（任意）の記録
- 配達完了登録（FR-044）：出荷済→配達完了（ST-PO-06）、配達完了日時の記録

対象外：

- ピッキング・梱包・発送の作業、配送業者の配達完了情報の確認（本システム外。FR-OUT-07）
- 配送業者との連携、配送日時指定（FR-OUT-07）
- 部分出荷・分割配送・返品（FR-OUT-04）
- 管理者による注文のキャンセル（UC-012）
- 出荷・配達完了の通知メール（FR-OUT-08）、帳票出力（FR-OUT-15）
- 出荷登録・配達完了登録の取消（状態の逆戻りは行わない）

## 3. 目的・開始条件



### 3.1 Goal

管理者（EC運営担当・出荷担当）が、全購入者の注文を条件で検索して内容（購入者・明細・配送先・決済記録・状態履歴）を確認し、支払済の注文の出荷を登録（配送伝票番号を含む）、出荷済の注文の配達完了を登録することで、購入者が注文状況を画面で確認できる状態にする。


### 3.2 Trigger

管理者がログイン後のトップである注文一覧（管理）（SCR-102）を開く。出荷登録は支払済注文の発送作業（本システム外）を終えたとき、配達完了登録は配送業者の配達完了情報を確認したとき（本システム外）に行う。管理者は同じ操作を画面または Web API で要求できる。


### 3.3 Precondition

| ID | 前提条件 | 満たさない場合の扱い |
|---|---|---|
| PRE-UC-011-001 | 管理者がログイン済みで、ログイン状態が有効期間内である。 | 開始不可。未ログイン・ログイン状態の期限切れは EX-01、購入者によるログインは EX-02 |
| PRE-UC-011-002 | 出荷登録の場合、対象の注文の状態が支払済であり、本システム外で発送を終えている。 | 支払済以外の注文は出荷登録を受け付けない（EX-05）。発送を終えていることは管理者が本システム外で確認する |
| PRE-UC-011-003 | 配達完了登録の場合、対象の注文の状態が出荷済であり、本システム外で配達完了を確認している。 | 出荷済以外の注文は配達完了登録を受け付けない（EX-05）。配達完了は管理者が本システム外で確認する |

## 7. Postcondition



### 7.1 正常終了

### 9.20 AC-UC-011-020：同一注文への同時の出荷登録は1件だけ成功する

| 項目 | 内容 |
|---|---|
| Type | 機能 |
| 関連Requirement ID | FR-043 |
| 関連Flow | EX-06 |
| 優先度 | 推奨 |

#### Given

- 管理者X（admin-01@example.com）と管理者Y（admin-02@example.com）がそれぞれログイン済み。
- 各試行の開始時点で、注文（所有者 購入者B、状態 支払済、明細 CUP-RED-03×1、注文状態履歴2件）を1件新たに用意し、在庫単位 CUP-RED-03 の在庫数量を記録する。


#### When

- 管理者Xが配送伝票番号 TRK-X、管理者Yが配送伝票番号 TRK-Y で、その注文の出荷登録を同時に行う。これを注文を作り直して10試行行う。


#### Then

- 各試行で、一方の出荷登録が完了し、もう一方には出荷登録できるのは支払済の注文に限る旨と現在の状態（出荷済）が通知される。
- 各試行で、支払済→出荷済の注文状態履歴は1件（合計3件）で、その実行した利用者と注文の配送伝票番号は、出荷登録が完了した側の管理者と配送伝票番号に一致する。
- 各試行で、在庫単位 CUP-RED-03 の在庫数量は試行開始時点から変化しない。

| 項目 | 内容 |

| 指標 | Then を満たした試行の数 |
| 目標値 | 10試行中10試行 |
| 測定条件 | 同一注文に2人の管理者が同時に出荷登録を行う。10試行 |
| 許容範囲 | 0試行（1試行でも満たさなければ不合格） |
| 検証方法 | 2件の出荷登録を同時に行い、各試行後に注文の状態・配送伝票番号・注文状態履歴を確認する。 |

| BLOCKED | 2件の出荷登録を同時に行う手段が無い場合。 |
