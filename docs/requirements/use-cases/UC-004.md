## 1. 本書の目的と適用範囲



### 1.1 目的

購入者（ACT-002）が、商品詳細で選んだ在庫単位（StockUnit）を自分のカート（Cart）に入れ、カート上で数量の変更と明細の削除を行い、注文確定の前に小計・割引額・割引後小計・送料・消費税額・合計金額の内訳を確認できるようにする。同一在庫単位の数量は10個以下かつ操作時点の在庫数量以下に保ち、カートに入れた時点では在庫を引き当てない（在庫数量を減らさない）。


### 1.2 適用範囲

| 区分 | 内容 |
|---|---|
| Use Case ID | UC-004 |
| 対象ユースケース | カートに商品を入れて数量を調整する |
| 対象リリース・範囲 | MiniCommerce 初期リリース |
| 本書で定義する | Goal、Actor、Trigger、Precondition、Flow、Postcondition、Business Rule、AC |
| 本書で定義しない | 新たな実装方式の決定。受領済みのAPI・画面条件は要求根拠として維持 |

対象範囲（原資料 In Scope）：

- カート照会（FR-020）：利用中（open）カートの明細・合計点数・適用中クーポンの判定結果・金額内訳を返す。利用中カートが無い場合は空のカートを作成して返す。
- カート明細追加（FR-021）：SCR-002 商品詳細からの在庫単位の投入。同一在庫単位は既存明細の数量に合算する。
- カート明細数量変更（FR-022）・カート明細削除（FR-023）：SCR-005 カートでの操作。
- 注文金額計算（FR-026）：カート照会・明細操作のたびに、照会・操作時点の税抜価格で金額内訳を算出する。
- 数量上限（同一在庫単位10個）と在庫数量による投入・数量変更の判定、未ログインの利用者・管理者による操作の拒否。

対象外（原資料 Out of Scope）：

- 商品の検索・閲覧と在庫単位の確認（UC-003）。
- クーポンの適用・解除の操作（UC-005）。ただし、適用中のクーポンがある状態での明細操作後の金額再計算は本UCに含む。
- 在庫引当・注文の作成・カートの注文済への変更（UC-006）。
- 未ログイン状態でのカート利用（ゲスト購入。FR-OUT-10）。
- 複数クーポンの併用、ポイント、自動適用の割引（FR-OUT-05）。

## 3. 目的・開始条件



### 3.1 Goal

購入者（ACT-002）が、商品詳細で選んだ在庫単位（StockUnit）を自分のカート（Cart）に入れ、カート上で数量の変更と明細の削除を行い、注文確定の前に小計・割引額・割引後小計・送料・消費税額・合計金額の内訳を確認できるようにする。同一在庫単位の数量は10個以下かつ操作時点の在庫数量以下に保ち、カートに入れた時点では在庫を引き当てない（在庫数量を減らさない）。


### 3.2 Trigger

購入者が SCR-002 商品詳細で在庫単位（規格）と数量を指定して「カートに入れる」を操作したとき、または共通ヘッダーの「カート」から SCR-005 カートを開いたとき。API では GET /api/cart、POST /api/cart/lines、PATCH /api/cart/lines/{cart_line_id}、DELETE /api/cart/lines/{cart_line_id} を受信したとき。


### 3.3 Precondition

| ID | 前提条件 | 満たさない場合の扱い |
|---|---|---|
| PRE-UC-004-001 | 購入者（ロール buyer）がログイン済みである（API は発行から24時間以内でログアウトにより無効化されていない認証トークン、画面は無操作30分以内のログインセッションを持つ）。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |
| PRE-UC-004-002 | 投入する在庫単位が存在し、その商品の公開状態が「公開」である。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |
| PRE-UC-004-003 | 商品・在庫単位・クーポン・利用者は初期データ一括投入（FR-060）で登録済みである。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |
| PRE-UC-004-004 | 購入者の利用中（open）カートは0件または1件である（1購入者につき最大1件）。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |


## 4. 基本フロー

| Step | Actor / System | 操作・振る舞い | 結果・状態 |
|---|---|---|---|
| 1 | 購入者 | SCR-002 商品詳細で在庫単位（規格）を選び、数量（1以上の整数）を入力して「カートに入れる」を操作する（FR-021） | カート明細追加の要求が送信される |
| 2 | System | 認証・権限・入力形式を判定し、在庫単位が存在し商品が公開であることを確認する。利用中カートが無ければ空のカート（状態 open）を作成する（FR-021） | 判定をすべて満たす。購入者の利用中カートは1件 |
| 3 | System | 合算数量（カート内の同一在庫単位の既存数量＋入力数量）が10以下、かつ現在の在庫数量以下であることを判定し、同一在庫単位の明細が無いため新しい明細を追加する（FR-021）。続いて金額内訳を算出する（FR-026） | カート明細が1行増える。在庫単位の在庫数量は変化しない |
| 4 | System | HTTPステータス200で更新後のカート表現を返す。画面は SCR-002 のまま、画面上部のメッセージ領域に完了メッセージを表示し、共通ヘッダーのカート合計点数を total_quantity の値に更新する | 購入者が追加結果を確認できる |
| 5 | 購入者 | 共通ヘッダーの「カート」を操作して SCR-005 カートを開く（FR-020） | カート照会の要求が送信される |
| 6 | System | 利用中カートの明細を追加日時昇順で、商品名・規格名・現在の単価（税込価格を主表示し税抜価格を併記）・数量・明細金額・現在の在庫数量とともに表示し、合計点数と金額内訳（小計・割引額・割引後小計・送料・消費税額・合計（税込））を表示する（FR-020, FR-026） | 表示内容は照会時点の税抜価格・在庫数量に基づく |
| 7 | 購入者 | SCR-005 で明細の数量を1以上の整数に書き換えて「数量を変更」を操作する（FR-022） | 数量変更の要求が送信される |
| 8 | System | 明細が自分の利用中カートにあること、変更後数量が10以下かつ現在の在庫数量以下であることを判定して数量を更新し、金額内訳を再計算する（FR-022, FR-026）。HTTPステータス200で更新後のカート表現を返し、SCR-005 を再表示する | 明細の数量が変更後の値になる。在庫数量は変化しない |
| 9 | 購入者 | 金額内訳を確認し、クーポンを使う場合は UC-005 へ、注文に進む場合は「注文手続きへ進む」を操作して UC-006（SCR-006 注文手続き）へ進む | 本UCは終了する。カートは利用中（open）のまま |
