## 1. 本書の目的と適用範囲



### 1.1 目的

管理者（EC運営担当）が、非公開商品を含む全在庫単位の在庫数量と低在庫（在庫数量5以下）を、SKU・商品名・仕入先・低在庫の条件で絞り込んで確認し、本システム外で行う補充の判断に使えるようにする。


### 1.2 適用範囲

| 区分 | 内容 |
|---|---|
| Use Case ID | UC-010 |
| 対象ユースケース | 在庫を確認する |
| 対象リリース・範囲 | MiniCommerce 初期リリース |
| 本書で定義する | Goal、Actor、Trigger、Precondition、Flow、Postcondition、Business Rule、AC |
| 本書で定義しない | 実装方式、画面デザイン詳細、物理データ構造、API・ファイルの物理仕様 |

対象範囲：

- 在庫単位一覧（管理）（SCR-101、FR-040）の表示
- 検索条件：SKU（前方一致）、商品名（部分一致）、仕入先（完全一致）、低在庫のみ（在庫数量5以下のみ）、ページ番号。条件間は「かつ」で組み合わせる（すべての条件を満たすもの）
- SKU昇順・1ページ50件の一覧の分割表示
- 注文確定（在庫引当）・キャンセル（在庫戻し）後の在庫数量の反映確認

対象外：

- 在庫数量の登録・変更、入荷・在庫補充の登録（FR-OUT-02、FR-OUT-03。稼働開始時の在庫数量は初期データ一括投入 UC-013 で登録）
- 商品・在庫単位・仕入先の登録・更新・削除（FR-OUT-02）
- 低在庫の通知（FR-OUT-08）、帳票・ファイル出力（FR-OUT-15）
- 実店舗在庫の管理

## 3. 目的・開始条件



### 3.1 Goal

管理者（EC運営担当）が、非公開商品を含む全在庫単位の在庫数量と低在庫（在庫数量5以下）を、SKU・商品名・仕入先・低在庫の条件で絞り込んで確認し、本システム外で行う補充の判断に使えるようにする。


### 3.2 Trigger

管理者が在庫単位一覧を開く。Web API で在庫単位一覧の照会を要求した場合も同じ。


### 3.3 Precondition

| ID | 前提条件 | 満たさない場合の扱い |
|---|---|---|
| PRE-UC-010-001 | 管理者がログイン済みで、ログイン状態の有効期間内である。 | ログインしていない、またはログイン状態の有効期間が切れている場合は EX-01、購入者の場合は EX-02 へ |
| PRE-UC-010-002 | 在庫単位が初期データ一括投入（UC-013、FR-060）で登録されている（0件の場合は空の一覧となる）。 | 在庫単位が0件の場合は0件の一覧を表示する（ALT-03 と同じ結果） |

## 7. Postcondition



### 7.1 正常終了

- 管理者が、条件を満たす在庫単位の在庫数量・低在庫かどうかを、SKU昇順・1ページ50件で確認できている。
- 表示される在庫数量は、照会時点までに確定した注文確定（減算）・キャンセル（加算）・初期データ一括投入をすべて反映した値である。
- 照会のみであり、在庫単位・注文は変化していない。


### 7.2 失敗終了

- エラー時も在庫単位・注文は変化しない。
- 購入者・来訪者に仕入先・非公開商品の在庫単位の情報は提供されない。

### 9.1 AC-UC-010-001：非公開商品を含む全在庫単位が SKU昇順で表示される

| 項目 | 内容 |
|---|---|
| Type | 機能 |
| 関連Requirement ID | FR-040 |
| 関連Flow | MAIN |
| 優先度 | 必須 |

#### Given

- 管理者X（admin-01@example.com）がログイン済み。
- 在庫単位は標準在庫データの5件のみ（在庫数量 MUG-BLK-01=6、MUG-WHT-01=5、PLATE-BLU-02=0、TOWEL-01=100、XMUG-01=30。XMUG-01 は非公開商品）。注文は0件。
