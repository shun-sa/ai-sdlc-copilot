## 1. 本書の目的と適用範囲



### 1.1 目的

購入者（ACT-002）が配送先を入力し、カートの内容で注文（PurchaseOrder）を確定して注文番号を受け取れるようにする。確定時には数量上限・クーポン条件・在庫を改めて判定し、全明細の在庫を一括で引き当て、確定時点の税抜価格で金額を確定する。1明細でも在庫が足りない場合は注文を確定せず、在庫数量を超える販売をしない。


### 1.2 適用範囲

| 区分 | 内容 |
|---|---|
| Use Case ID | UC-006 |
| 対象ユースケース | 注文を確定する |
| 対象リリース・範囲 | MiniCommerce 初期リリース |
| 本書で定義する | Goal、Actor、Trigger、Precondition、Flow、Postcondition、Business Rule、AC |
| 本書で定義しない | 新たな実装方式の決定。受領済みのAPI・画面条件は要求根拠として維持 |

対象範囲（原資料 In Scope）：

- 注文確定（FR-030）：配送先の入力検証、確定時の再判定（商品の公開状態・数量上限・クーポン条件・在庫数量）、全明細の在庫の一括引当、注文番号の採番、注文・注文明細・配送先・注文状態履歴の登録、カートの注文済（converted）への変更。
- 注文金額計算（FR-026）：確定時刻と確定時点の税抜価格による金額の確定。
- 同時確定・二重送信のときの整合（在庫数量が0未満にならない、同一カートから作成される注文は1件）。
- SCR-006 注文手続き（配送先入力・確認）と SCR-007 注文完了の表示。

対象外（原資料 Out of Scope）：

- カート明細の操作（UC-004）とクーポンの適用・解除（UC-005）。
- 支払（UC-007）、注文履歴・注文詳細の照会（UC-008）、注文のキャンセルと在庫戻し（UC-009, UC-012）。
- 配送日時指定、住所検証、送料の地域別設定（FR-OUT-07）。
- 注文確認メールを含む通知（FR-OUT-08）。
- 未払い注文の自動キャンセル（FR-OUT-12）。

## 3. 目的・開始条件



### 3.1 Goal

購入者（ACT-002）が配送先を入力し、カートの内容で注文（PurchaseOrder）を確定して注文番号を受け取れるようにする。確定時には数量上限・クーポン条件・在庫を改めて判定し、全明細の在庫を一括で引き当て、確定時点の税抜価格で金額を確定する。1明細でも在庫が足りない場合は注文を確定せず、在庫数量を超える販売をしない。


### 3.2 Trigger

購入者が SCR-006 注文手続きで配送先を入力して「注文を確定する」を操作し、確認ダイアログで承諾したとき。API では POST /api/checkout を受信したとき。


### 3.3 Precondition

| ID | 前提条件 | 満たさない場合の扱い |
|---|---|---|
| PRE-UC-006-001 | 購入者（ロール buyer）がログイン済みである（API は発行から24時間以内でログアウトにより無効化されていない認証トークン、画面は無操作30分以内のログインセッションを持つ）。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |
| PRE-UC-006-002 | 購入者の利用中（open）カートに明細が1件以上ある（UC-004）。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |
| PRE-UC-006-003 | クーポンを使う場合は、利用中カートにクーポンが適用されている（UC-005）。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |

| 5 | System | 認証・権限を判定し、配送先の全項目を検証する。前後空白を除去し、郵便番号は「数字7桁」または「数字3桁-数字4桁」の形式であること、電話番号は数字とハイフンのみでハイフン除去後の桁数を判定する（FR-030） | 入力に不備が無い |
| 6 | System | カート明細が1件以上あること、全明細の商品が公開であること、各明細の数量が10以下であること、クーポン適用中なら確定時刻で有効期間と最低購入金額を満たすこと、全明細の数量が現在の在庫数量以下であることを、この順に判定する（FR-030） | 判定をすべて満たす |
| 7 | System | 一括の処理として、全明細の在庫数量を注文数量分減らし、確定時刻と確定時点の税抜価格で金額を確定し（FR-026）、注文を作成する（注文番号「PO-」＋8桁、状態 created（注文受付）、注文日時、明細のスナップショット（在庫単位ID・SKU・商品名・規格名・税抜単価・数量・明細金額）、クーポンのスナップショット（コード・割引方式・割引値）、各金額、配送先）。注文状態履歴を1件（変更前なし→created、実行者は購入者）記録し、カートを注文済（converted）にして注文済日時を記録する（FR-030） | すべて成功するか、何も変更しないかのどちらか |
| 8 | System | HTTPステータス201で注文詳細表現を返し、SCR-007 注文完了に注文番号・合計金額と「支払へ進む」「注文詳細を見る」を表示する。共通ヘッダーのカート合計点数は0になる | 注文は状態 created（注文受付） |
| 9 | 購入者 | 「支払へ進む」（UC-007）または「注文詳細を見る」（UC-008）を操作する | 本UCは終了する。以後のカート操作は新しい空の利用中カートで行う |

## 7. Postcondition



### 7.1 正常終了

- 注文が1件作成され、状態は created（注文受付）、注文番号は「PO-」＋8桁の数字で全注文の中で一意である。
- 注文の全明細について、在庫単位の在庫数量が注文数量分減っている（在庫数量は0以上）。
- 注文明細・クーポン・金額・配送先は確定時点の値で記録され、以後の価格変更の影響を受けない。
- 注文状態履歴が1件（変更前なし→created、実行者の区分 buyer）記録されている。
- 確定に使ったカートは注文済（converted）で注文済日時が記録され、以後変更されない。購入者の次のカート照会は新しい空の利用中カートを返す。


### 7.2 失敗終了

- エラー応答（HTTPステータス400／401／403／409／500）の場合、在庫数量・注文・注文明細・配送先・注文状態履歴・カート（明細・クーポンの適用・状態）はすべて操作前の状態のまま。注文番号の欠番は許容する。
- どの在庫単位の在庫数量も0未満にならない。
