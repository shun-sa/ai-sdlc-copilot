## 1. 本書の目的と適用範囲



### 1.1 目的

購入者（ACT-002）が配送先を入力し、カートの内容で注文を確定して注文番号を受け取れるようにする。確定時には数量上限・クーポン条件・在庫を改めて判定し、全明細の在庫を一括で引き当て、確定時点の税抜価格で金額を確定する。1明細でも在庫が足りない場合は注文を確定せず、在庫数量を超える販売をしない。


### 1.2 適用範囲

| 区分 | 内容 |
|---|---|
| Use Case ID | UC-006 |
| 対象ユースケース | 注文を確定する |
| 対象リリース・範囲 | MiniCommerce 初期リリース |
| 本書で定義する | Goal、Actor、Trigger、Precondition、Flow、Postcondition、Business Rule、AC |
| 本書で定義しない | 実装方式、画面デザイン詳細、物理データ構造、API・ファイルの物理仕様 |

対象範囲：

- 注文確定（FR-030）：配送先の入力検証、確定時の再判定（商品の公開状態・数量上限・クーポン条件・在庫数量）、全明細の在庫の一括引当、注文番号の採番、注文・注文明細・配送先・注文状態履歴の登録、カートの注文済への変更。
- 注文金額計算（FR-026）：確定時刻と確定時点の税抜価格による金額の確定。
- 同時確定・二重送信のときの整合（在庫数量が0未満にならない、同一カートから作成される注文は1件）。
- SCR-006 注文手続き（配送先入力・確認）と SCR-007 注文完了の表示。

対象外：

- カート明細の操作（UC-004）とクーポンの適用・解除（UC-005）。
- 支払（UC-007）、注文履歴・注文詳細の照会（UC-008）、注文のキャンセルと在庫戻し（UC-009, UC-012）。
- 配送日時指定、住所検証、送料の地域別設定（FR-OUT-07）。
- 注文確認メールを含む通知（FR-OUT-08）。
- 未払い注文の自動キャンセル（FR-OUT-12）。

## 3. 目的・開始条件



### 3.1 Goal

購入者（ACT-002）が配送先を入力し、カートの内容で注文を確定して注文番号を受け取れるようにする。確定時には数量上限・クーポン条件・在庫を改めて判定し、全明細の在庫を一括で引き当て、確定時点の税抜価格で金額を確定する。1明細でも在庫が足りない場合は注文を確定せず、在庫数量を超える販売をしない。


### 3.2 Trigger

購入者が SCR-006 注文手続きで配送先を入力して「注文を確定する」を操作し、確定してよいかの確認に承諾したとき。または、購入者が Web API で注文確定を要求したとき。


### 3.3 Precondition

| ID | 前提条件 | 満たさない場合の扱い |
|---|---|---|
| PRE-UC-006-001 | 購入者がログイン済みである（ログイン状態の有効期間内である）。 | 開始不可。未ログインの場合は EX-01、管理者の場合は EX-02 |
| PRE-UC-006-002 | 購入者の利用中カートに明細が1件以上ある（UC-004）。 | 確定不可。EX-04 |
| PRE-UC-006-003 | クーポンを使う場合は、利用中カートにクーポンが適用されている（UC-005）。 | クーポンの割引なしで確定する（ALT-01 を経由しない） |


## 4. 基本フロー

| Step | Actor / System | 操作・振る舞い | 結果・状態 |
|---|---|---|---|
| 1 | 購入者 | SCR-005 カートで「注文手続きへ進む」を操作する | SCR-006 注文手続きの表示を要求する |
| 2 | System | SCR-006 に、カートの明細（商品名・規格名・税込単価と税抜単価・数量）、適用中クーポン、金額内訳（小計・割引額・割引後小計・送料・消費税額・合計（税込））と、配送先の入力項目（受取人氏名・郵便番号・都道府県・住所1（市区町村・番地）・住所2（建物名・部屋番号。任意）・電話番号）を表示する（FR-020, FR-026） | 表示時点の金額内訳が表示される。カート・在庫は変化しない |
| 3 | 購入者 | 配送先を入力し、「注文を確定する」を操作する | 確定してよいかの確認が求められる |
| 4 | 購入者 | 確定の確認に承諾する | 注文確定の要求（FR-030）が送信される。処理が完了するまでの間に「注文を確定する」を繰り返し操作しても、注文確定は1回分だけ反映される（処理の完了後に行った操作は新たな操作として扱う） |
| 5 | System | ログイン状態と権限を判定し、配送先の全項目を検証する。前後空白を除去し、郵便番号は「数字7桁」または「数字3桁-数字4桁」の形式であること、電話番号は数字とハイフンのみでハイフン除去後の桁数を判定する（FR-030） | 入力に不備が無い |
| 6 | System | カート明細が1件以上あること、全明細の商品が公開であること、各明細の数量が10以下であること、クーポン適用中なら確定時刻で有効期間と最低購入金額を満たすこと、全明細の数量が現在の在庫数量以下であることを、この順に判定する（FR-030） | 判定をすべて満たす |
| 7 | System | 全明細の在庫数量を注文数量分減らし、確定時刻と確定時点の税抜価格で金額を確定し（FR-026）、注文を作成する（注文番号「PO-」に続く数字8桁、注文状態は注文受付、注文日時、確定時点の明細の内容（在庫単位・SKU・商品名・規格名・税抜単価・数量・明細金額）、クーポンの内容（コード・割引方式・割引値）、各金額、配送先）。注文状態履歴を1件（変更前なし→注文受付、実行者は購入者）記録し、カートを注文済にして注文済日時を記録する（FR-030） | 途中で失敗した場合は、在庫数量・カート・注文のいずれも処理前の状態から変化しない |
| 8 | System | 確定した注文の内容を通知し、SCR-007 注文完了に注文番号・合計金額と「支払へ進む」「注文詳細を見る」を表示する。カートの合計点数表示は0になる | 注文状態は注文受付 |
| 9 | 購入者 | 「支払へ進む」（UC-007）または「注文詳細を見る」（UC-008）を操作する | 本UCは終了する。以後のカート操作は新しい空の利用中カートで行う |

## 7. Postcondition



### 7.1 正常終了

- 注文が1件作成され、注文状態は注文受付、注文番号は「PO-」に続く数字8桁で全注文の中で一意である。
- 注文の全明細について、在庫単位の在庫数量が注文数量分減っている（在庫数量は0以上）。
- 注文明細・クーポン・金額・配送先は確定時点の値で記録され、以後の価格変更の影響を受けない。
- 注文状態履歴が1件（変更前なし→注文受付、実行者は購入者）記録されている。
- 確定に使ったカートは注文済で注文済日時が記録され、以後変更されない。購入者が次にカートを照会すると、新しい空の利用中カートが表示される。


### 7.2 失敗終了

- 注文確定がエラー（認証・権限・入力・業務・システムのいずれのエラーも）となった場合、在庫数量・注文・注文明細・配送先・注文状態履歴・カート（明細・クーポンの適用・状態）はすべて操作前の状態のまま。
- どの在庫単位の在庫数量も0未満にならない。
- 注文番号の欠番は許容する。
