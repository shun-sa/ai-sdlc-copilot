## 1. 本書の目的と適用範囲



### 1.1 目的

来訪者が、メールアドレス・パスワード・氏名を登録して MiniCommerce の会員（ロール buyer の購入者）となり、以後ログイン（UC-002）してカート・注文の機能を利用できる状態にする。


### 1.2 適用範囲

| 区分 | 内容 |

対象範囲（原資料 In Scope）：

- 会員登録画面（SCR-003）からの会員登録と、同じ機能を提供する Web API（POST /api/auth/register）による会員登録（FR-001）
- 入力値の検証（必須・文字数・メールアドレス形式・パスワード条件・確認用パスワードの一致）と、不備のある全項目の一括返却
- メールアドレスの正規化（前後空白の除去・英小文字化）と、正規化後の値による登録済み判定
- ロール buyer の利用者の登録と、パスワードのソルト付き一方向ハッシュによる保存
- 登録完了後のログイン画面（SCR-004）への遷移と完了メッセージの表示
- 同一メールアドレスの同時登録の制御

対象外（原資料 Out of Scope）：

- ログイン・ログアウト（UC-002）
- 管理者アカウントの作成（初期データ一括投入でのみ作成する。UC-013）
- 会員情報の変更、パスワード再設定、退会（FR-OUT-09）
- 登録確認メールの送信・メールアドレスの到達確認（FR-OUT-08）

## 3. 目的・開始条件



### 3.1 Goal

来訪者が、メールアドレス・パスワード・氏名を登録して MiniCommerce の会員（ロール buyer の購入者）となり、以後ログイン（UC-002）してカート・注文の機能を利用できる状態にする。


### 3.2 Trigger

来訪者が会員登録画面（SCR-003）で入力項目を入力して登録を実行したとき。Web API では POST /api/auth/register の要求を受け付けたとき。


### 3.3 Precondition

|---|---|---|
| PRE-UC-001-001 | MiniCommerce が稼働している（計画停止中でない）。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |
| PRE-UC-001-002 | 会員登録は認証を必要としない。ログインしていない来訪者が実行でき、購入者・管理者がログイン中に実行した場合も受け付ける。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |
| PRE-UC-001-003 | 来訪者が SCR-003 を表示できる、または Web API に要求を送信できる。 | 原資料では前提ごとの個別対応は未記載。機能要件と6章の例外フローを参照 |

## 7. Postcondition



### 7.1 正常終了

- 正規化後のメールアドレスで利用者（User）が1件登録され、role は buyer、registered_at は処理時刻（JST）である。
- パスワードはソルト付き一方向ハッシュ値のみが保存され、平文は保存されていない。
- 認証トークン・ログインセッションは発行されておらず、来訪者は未ログインのままである。
- 登録したメールアドレス（英大文字・前後空白を含めて入力しても可）とパスワードで UC-002 のログインができる。


### 7.2 失敗終了

- 利用者（User）の件数・内容は操作前のままである（部分的な登録を残さない）。
- エラー応答は error.code・error.message・error.details・error.context の形式で返され（context は該当なしの場合は空オブジェクト）、スタックトレース・SQL 文を含まない。
- 入力されたパスワード・メールアドレス・氏名はアプリケーションログ・監査ログに出力されない。

## 9. Acceptance Criteria / 合否判定基準



### 9.1 AC-UC-001-001：正常な会員登録（API）

| 項目 | 内容 |
|---|---|
| Type | 機能 |
| 関連Requirement ID | FR-001 |
| 関連Flow | MAIN, ALT-03 |
| 優先度 | 必須 |

#### Given

- 利用者（User）に email「hanako.sato@example.com」の利用者が存在しない。
- 要求に Authorization ヘッダーを付けない。


#### When

- POST /api/auth/register に email「hanako.sato@example.com」、password「Passw0rd」、password_confirmation「Passw0rd」、full_name「佐藤 花子」を送信する。要求送信時刻と応答受信時刻を記録する。


#### Then

- HTTP ステータスが 201 である。
- 応答本文の email が「hanako.sato@example.com」、full_name が「佐藤 花子」、role が「buyer」であり、user_id に値がある。
