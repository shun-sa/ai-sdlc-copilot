## 1. 本書の目的と適用範囲

### 1.1 目的

来訪者が、メールアドレス・パスワード・氏名を登録して MiniCommerce の会員（購入者）となり、以後ログイン（UC-002）してカート・注文の機能を利用できる状態にする。

### 1.2 適用範囲

| 区分 | 内容 |
|---|---|
| Use Case ID | UC-001 |
| 対象ユースケース | 会員登録する |
| 対象リリース・範囲 | MiniCommerce 初期リリース |
| 本書で定義する | Goal、Actor、Trigger、Precondition、Main/Alternative/Exception Flow、Postcondition、Business Rule、Acceptance Criteria |
| 本書で定義しない | 実装方式、画面デザイン詳細、物理データ構造、API・ファイルの物理仕様 |

対象範囲：

- 会員登録画面（SCR-003）からの会員登録と、同じ機能を提供する Web API による会員登録（FR-001）
- 入力値の検証（必須・文字数・メールアドレス形式・パスワード条件・確認用パスワードの一致）と、不備のある全項目の一括通知
- メールアドレスの正規化（前後空白の除去・英小文字化）と、正規化後の値による登録済み判定
- 購入者としての利用者の登録
- 登録完了後のログイン画面（SCR-004）への遷移と完了メッセージの表示
- 同一メールアドレスの同時登録時の結果

対象外：

- ログイン・ログアウト（UC-002）
- 管理者アカウントの作成（初期データ一括投入でのみ作成する。UC-013）
- 会員情報の変更、パスワード再設定、退会（FR-OUT-09）
- 登録確認メールの送信・メールアドレスの到達確認（FR-OUT-08）

## 3. 目的・開始条件

### 3.1 Goal

来訪者が、メールアドレス・パスワード・氏名を登録して MiniCommerce の会員（購入者）となり、以後ログイン（UC-002）してカート・注文の機能を利用できる状態にする。

### 3.2 Trigger

来訪者が会員登録画面（SCR-003）で入力項目を入力して登録を実行したとき。または Web API で会員登録を要求したとき。

### 3.3 Precondition

| ID | 前提条件 | 満たさない場合の扱い |
|---|---|---|
| PRE-UC-001-001 | MiniCommerce が稼働している（計画停止中でない）。 | 開始不可。処理中に障害が発生した場合は EX-04 |
| PRE-UC-001-002 | 会員登録は認証を必要としない。ログインしていない来訪者が実行でき、購入者・管理者がログイン中に実行した場合も受け付ける。 | 該当なし（ログイン状態にかかわらず開始できる。ログイン中の場合は ALT-04） |
| PRE-UC-001-003 | 来訪者が SCR-003 を表示できる、または Web API で要求できる。 | 開始不可 |

## 7. Postcondition

### 7.1 正常終了

- 正規化後のメールアドレスで利用者が1件登録され、利用者区分は購入者、登録日時は処理時刻（JST）である。
- パスワードは平文・復号可能な形式で保持されていない（NFR-SC-01）。
- 来訪者はログイン状態になっておらず、未ログインのままである。
- 登録したメールアドレス（英大文字・前後空白を含めて入力しても可）とパスワードで UC-002 のログインができる。

### 7.2 失敗終了

- 利用者の件数・内容は操作前のままである（部分的な登録を残さない）。
- 入力されたパスワード・メールアドレス・氏名はアプリケーションログ・監査ログに出力されない。

## 9. Acceptance Criteria / 合否判定基準

### 9.1 AC-UC-001-001：正常な会員登録（Web API）

| 項目 | 内容 |
|---|---|
| Type | 機能 |
| 関連Requirement ID | FR-001 |
| 関連Flow | MAIN, ALT-03 |
| 優先度 | 必須 |

#### Given

- メールアドレス「hanako.sato@example.com」の利用者が存在しない。
- ログインしていない状態で要求する。

#### When

- Web API で、メールアドレス「hanako.sato@example.com」、パスワード「Passw0rd」、パスワード（確認用）「Passw0rd」、氏名「佐藤 花子」を指定して会員登録を要求する。要求時刻と応答時刻を記録する。

#### Then

- 登録が完了し、登録された利用者のメールアドレス「hanako.sato@example.com」、氏名「佐藤 花子」、利用者区分「購入者」と、利用者IDが通知される。
- 通知された登録日時が JST の日時であり、要求時刻から応答時刻までの範囲内である（秒単位で判定）。
- 通知内容にパスワードが含まれず、ログイン状態にもならない（ログイン状態の有効期限等は通知されない）。
- 利用者が操作前より1件多く、追加された利用者のメールアドレスが「hanako.sato@example.com」、利用者区分が購入者である。
- 監査ログにログイン成功が記録されない（自動でログインしない）。
