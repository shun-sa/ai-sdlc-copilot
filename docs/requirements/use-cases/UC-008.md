## 1. 本書の目的と適用範囲



### 1.1 目的

購入者が、問い合わせをせずに自分の注文の一覧と各注文の状況（状態・支払日時・出荷日時・配送伝票番号・配達完了日時・キャンセル日時）、金額の内訳、明細、配送先、状態の変更経過を確認でき、状態に応じて支払・キャンセルへ進める。


### 1.2 適用範囲

| 区分 | 内容 |
|---|---|
| Use Case ID | UC-008 |
| 対象ユースケース | 注文履歴・注文状況を確認する |
| 対象リリース・範囲 | MiniCommerce 初期リリース |
| 本書で定義する | Goal、Actor、Trigger、Precondition、Flow、Postcondition、Business Rule、AC |
| 本書で定義しない | 実装方式、画面デザイン詳細、物理データ構造、API・ファイルの物理仕様 |

対象範囲：

- 注文履歴一覧（SCR-009、FR-032）：自分の注文のみ、注文日時降順、1ページ20件
- 注文詳細（SCR-010、FR-033）：金額・明細（注文確定時点の内容）・クーポン・配送先・各日時・配送伝票番号・状態履歴（変更日時昇順）、支払可否・キャンセル可否
- 注文詳細から支払（UC-007）・キャンセル（UC-009）への導線の表示

対象外：

- 支払の実行（UC-007）、キャンセルの実行（UC-009）
- 決済記録の参照（購入者は参照できない）
- 他の購入者の注文の参照、管理者による全注文の検索（UC-011）
- 帳票・ファイル出力（FR-OUT-15）、注文状況の通知メール（FR-OUT-08）
- 注文履歴の検索条件の指定（本UCの一覧はページ指定のみ）

## 3. 目的・開始条件



### 3.1 Goal

購入者が、問い合わせをせずに自分の注文の一覧と各注文の状況（状態・支払日時・出荷日時・配送伝票番号・配達完了日時・キャンセル日時）、金額の内訳、明細、配送先、状態の変更経過を確認でき、状態に応じて支払・キャンセルへ進める。


### 3.2 Trigger

購入者が注文履歴を開く、または注文完了画面（SCR-007）の「注文詳細を見る」を操作する。Web API で注文履歴一覧・注文詳細の照会を要求した場合も同じ。


### 3.3 Precondition

| ID | 前提条件 | 満たさない場合の扱い |
|---|---|---|
| PRE-UC-008-001 | 購入者がログイン済みで、ログイン状態の有効期間内である。 | ログインしていない、またはログイン状態の有効期間が切れている場合は EX-01、管理者の場合は EX-02 へ |
| PRE-UC-008-002 | 注文詳細を表示する場合、対象の注文がログイン中の購入者の注文として存在する。 | EX-04 へ |

## 7. Postcondition



### 7.1 正常終了

- 購入者が自分の注文だけを、注文日時降順・1ページ20件で確認できている。
- 注文詳細で、注文確定時点の明細・金額、配送先、現在の状態と各日時、配送伝票番号、状態履歴（変更日時昇順）が表示され、「支払う」「キャンセルする」の表示が注文の状態に一致している。
- 照会のみであり、注文・在庫・決済記録・注文状態履歴は変化していない。


### 7.2 失敗終了

- エラー時も注文・在庫・決済記録・注文状態履歴は変化しない。
- 他の購入者の注文の存在有無・内容は、通知・画面に現れない。

### 9.1 AC-UC-008-001：自分の注文だけが注文日時降順で一覧表示される

| 項目 | 内容 |
|---|---|
| Type | 機能 |
| 関連Requirement ID | FR-032, NFR-SC-03 |
| 関連Flow | MAIN |
| 優先度 | 必須 |

#### Given

- 購入者A（buyer-a@example.com）がログイン済み。
- 購入者Aの注文：PO-00000001（注文日時 2027-04-01 10:00、状態 注文受付、合計5,500円、明細の数量合計2）、PO-00000003（注文日時 2027-04-02 09:00、状態 支払済、合計6,048円、数量合計1）、PO-00000004（注文日時 2027-04-03 15:30、状態 出荷済、合計6,044円、数量合計3）。
- 購入者B（buyer-b@example.com）の注文：PO-00000002（注文日時 2027-04-01 12:00、状態 注文受付、合計3,300円）。


#### When

- 購入者Aがページを指定せずに注文履歴一覧を照会する。


#### Then

- 注文が3件、PO-00000004、PO-00000003、PO-00000001 の順に表示される。PO-00000002 は含まれない。
- 各注文の項目は注文番号、注文日時、注文状態、合計金額、合計点数。PO-00000004 は注文日時 2027-04-03 15:30、状態 出荷済、合計6,044円、合計点数3。
- ページ番号1、1ページの件数20、総件数3、総ページ数1が示される。


#### 測定・許容条件

| 項目 | 内容 |
|---|---|
| 指標 | 該当なし |
| 目標値 | 該当なし |
| 測定条件 | 該当なし |
| 許容範囲 | 該当なし |
| 検証方法 | 該当なし |


#### Pass / Fail Rule

| 判定 | 条件 |
|---|---|
| PASS | Then の全項目を満たす。 |
| FAIL | 他の購入者の注文が含まれる、並び順・件数・項目値が Then と一致しない。 |
| BLOCKED | 2名の試験用購入者と注文を用意できない場合。 |


#### Evidence

- 表示された注文履歴一覧の内容、登録されている注文の内容。
