## 1. 本書の目的と適用範囲



### 1.1 目的

購入者が、自分の注文受付状態の注文について、注文の合計金額を模擬決済で支払い、注文を支払済にする。支払の結果（承認・否認・連携エラー）は決済記録として残り、否認・連携エラーの場合は注文受付のまま再度支払える。


### 1.2 適用範囲

| 区分 | 内容 |
|---|---|
| Use Case ID | UC-007 |
| 対象ユースケース | 注文の代金を支払う（模擬決済） |
| 対象リリース・範囲 | MiniCommerce 初期リリース |
| 本書で定義する | Goal、Actor、Trigger、Precondition、Flow、Postcondition、Business Rule、AC |
| 本書で定義しない | 実装方式、画面デザイン詳細、物理データ構造、API・ファイルの物理仕様 |

対象範囲：

- 支払画面（SCR-008）での注文番号・合計金額の表示（FR-033）と、「模擬決済の結果」（承認／否認）を選択した支払（FR-031）
- Web API からの支払（FR-031）
- 決済サービス（模擬）への決済要求（注文番号・決済金額・通貨（日本円）・模擬決済指示の指定）と、承認・否認・応答なし（10秒超過）・応答不正の各結果の処理
- 決済記録（承認／否認／連携エラー）の登録、注文状態の注文受付→支払済の遷移（ST-PO-02）、支払日時と注文状態履歴の記録
- 同一注文への同時支払の制御

対象外：

- 実在の決済サービスとの連携（FR-OUT-01）
- 返金（支払済注文のキャンセル時の返金は本システム外で行う。FR-OUT-04）
- 注文確定（UC-006）、注文のキャンセル（UC-009、UC-012）
- 未払い注文の自動キャンセル（FR-OUT-12）
- 支払完了の通知メール（FR-OUT-08）
- 決済要求の自動再送（二重決済防止のため行わない）

## 3. 目的・開始条件



### 3.1 Goal

購入者が、自分の注文受付状態の注文について、注文の合計金額を模擬決済で支払い、注文を支払済にする。支払の結果（承認・否認・連携エラー）は決済記録として残り、否認・連携エラーの場合は注文受付のまま再度支払える。


### 3.2 Trigger

購入者が、注文完了画面（SCR-007）の「支払へ進む」または注文詳細画面（SCR-010）の「支払う」を操作し、支払画面（SCR-008）で「支払う」を操作する。または、購入者が Web API で支払を要求する。


### 3.3 Precondition

| ID | 前提条件 | 満たさない場合の扱い |
|---|---|---|
| PRE-UC-007-001 | 購入者がログイン済みである（ログイン状態の有効期間内である）。 | 開始不可。未ログインの場合は EX-01、管理者の場合は EX-02 |
| PRE-UC-007-002 | 支払対象の注文が、ログイン中の購入者が注文確定（UC-006、FR-030）した注文として存在する。 | 支払不可。EX-04 |
| PRE-UC-007-003 | 支払を完了するには、注文の注文状態が注文受付である。 | 支払不可。EX-05 |
| PRE-UC-007-004 | 決済サービス（模擬）が利用できる状態である（外部ネットワークへは接続しない。NFR-EN-05）。 | 応答なし・応答不正の場合は EX-07 |


## 4. 基本フロー

| Step | Actor / System | 操作・振る舞い | 結果・状態 |
|---|---|---|---|
| 1 | 購入者 | 注文詳細画面（SCR-010）で、支払可能な注文のときに表示される「支払う」を操作する | 注文は注文受付 |
| 2 | System | 支払画面（SCR-008）に注文番号・合計金額（例「5,500円」）と「模擬決済の結果」の選択肢（承認／否認、初期選択は承認）を表示する（FR-033） | 変更なし |
| 3 | 購入者 | 「模擬決済の結果」を承認のまま「支払う」を操作する | 処理が完了するまでの間に「支払う」を繰り返し操作しても、決済要求は1回分だけ送信される。否認・連携エラーの後に行った操作は新たな支払として扱う（FR-031） |
| 4 | System | ①ログイン状態 →②権限（購入者であること）→③入力（模擬決済指示が承認または否認であること）→④注文の存在と所有 →⑤注文状態が注文受付であること、の順に判定する（FR-031） | 変更なし |
| 5 | System | 決済サービス（模擬）へ注文番号・決済金額（注文の合計金額）・通貨（日本円）・模擬決済指示（承認）を渡して決済を要求し、応答を最大10秒待つ（FR-031） | 変更なし |
| 6 | 決済サービス（模擬） | 承認の結果、取引参照番号、処理日時を返す | 変更なし |
| 7 | System | 決済記録（結果 承認、取引参照番号、金額＝合計金額、処理日時）を登録し、注文状態を支払済にして支払日時を記録し、注文状態履歴（変更前 注文受付→変更後 支払済、実行者は支払った購入者）を1件記録する。途中で失敗した場合は、いずれも処理前の状態から変化しない（FR-031） | 注文は支払済（ST-PO-02）、承認の決済記録1件、在庫数量は変化しない |
| 8 | System | 支払後の注文の内容（注文状態 支払済、支払不可、キャンセル可）を通知する。画面は注文詳細画面（SCR-010）へ遷移し、支払完了の旨を表示する | 注文は支払済 |

## 7. Postcondition



### 7.1 正常終了

- 注文の注文状態が支払済で、支払日時に処理時刻が記録されている。
- 当該注文の決済記録に結果が承認のものが1件あり、取引参照番号が記録され、金額は注文の合計金額と一致する。
- 注文状態履歴に、変更前 注文受付→変更後 支払済、実行者は支払った購入者の履歴が1件追加されている。
- 在庫数量、注文の各金額・明細・配送先・注文日時は変化していない。
- 注文詳細で支払不可・キャンセル可となる。


### 7.2 失敗終了

- 否認・連携エラーの場合：注文の注文状態は注文受付、支払日時は値なし、注文状態履歴は増えない。決済記録に否認または連携エラーが1件追加される以外の変更はない。購入者は再度支払える。
- 認証・権限・入力・対象なし・状態不正のエラーの場合：注文・決済記録・注文状態履歴・在庫数量は一切変化せず、決済サービス（模擬）へ要求しない。
- いずれの場合も、1注文あたりの承認の決済記録は最大1件である。

### 9.18 AC-UC-007-019：同一注文への支払とキャンセルの同時実行は、逐次実行したいずれかの順序の結果と一致する

| 項目 | 内容 |
|---|---|
| Type | データ |
| 関連Requirement ID | FR-031, FR-034 |
| 関連Flow | EX-10 |
| 優先度 | 必須 |

#### Given

- 購入者Aがログイン済み。
- 各試行の開始時点で、注文（所有者 購入者A、注文状態 注文受付、明細 MUG-WHT-01×2、合計5,500円、決済記録0件、注文状態履歴1件）を1件新たに用意する。在庫単位 MUG-WHT-01 の在庫数量は各試行の開始時点の値を記録する。


#### When

- 購入者Aが、その注文について模擬決済指示を承認とした支払とキャンセル（FR-034）を同時に要求する（2要求の送信開始時刻の差は10ミリ秒以内）。これを注文を作り直して10試行行う。


#### Then

- 各試行で、キャンセルは受け付けられる（注文状態 キャンセル済）。
- 各試行で、支払の結果は次の (a)(b) のいずれかで、それぞれの条件を満たす。(a) 支払が行われず、状態不正として、現在の注文状態では支払えない旨と現在の注文状態（キャンセル済）が通知される：決済記録0件、注文状態履歴2件（注文受付→キャンセル済）、決済サービス（模擬）は当該注文の決済要求を受けていない。(b) 支払が受け付けられる（注文状態 支払済）：決済記録は承認1件のみ、注文状態履歴3件（注文受付→支払済、支払済→キャンセル済の順）。
- 各試行で、注文の最終的な注文状態はキャンセル済、在庫単位 MUG-WHT-01 の在庫数量は試行開始時点の値＋2（在庫戻しは1回だけ）。


#### 測定・許容条件

| 項目 | 内容 |
|---|---|
| 指標 | Then を満たした試行の数（あわせて (a)(b) それぞれの発生件数を記録する） |
| 目標値 | 10試行中10試行 |
| 測定条件 | Given・When に示す条件で10試行を行う |
| 許容範囲 | 0試行（1試行でも満たさなければ不合格） |
| 検証方法 | 支払とキャンセルを同時に要求し、各試行後に注文・決済記録・注文状態履歴・在庫数量と、決済サービス（模擬）が受けた決済要求の記録を確認する。 |


#### Pass / Fail Rule

| 判定 | 条件 |
|---|---|
| PASS | 10試行すべてで Then の全項目を満たす。 |
| FAIL | 1試行でも、キャンセルが受け付けられない、支払の結果が (a)(b) のいずれにも一致しない（(a) で決済記録が登録される、(b) で承認が2件以上になる場合を含む）、在庫数量が試行開始時点の値＋2 でない、または最終的な注文状態がキャンセル済でない。 |
| BLOCKED | 2件の要求を同時に送信できない場合。 |


#### Evidence

- 各試行の操作結果として通知された内容と要求時刻、決済サービス（模擬）が受けた決済要求の記録、注文・決済記録・注文状態履歴の内容、在庫単位の在庫数量。
