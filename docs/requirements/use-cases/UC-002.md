## 1. 本書の目的と適用範囲

### 1.1 目的

会員登録済みの購入者、および管理者が、メールアドレスとパスワードで本人であることを示してログインし、利用者区分（購入者／管理者）に応じた機能を利用できる状態になる。利用後はログアウトして、使っていたログイン状態を解除する。

### 1.2 適用範囲

| 区分 | 内容 |
|---|---|
| Use Case ID | UC-002 |
| 対象ユースケース | ログイン・ログアウトする |
| 対象リリース・範囲 | MiniCommerce 初期リリース |
| 本書で定義する | Goal、Actor、Trigger、Precondition、Main/Alternative/Exception Flow、Postcondition、Business Rule、Acceptance Criteria |
| 本書で定義しない | 実装方式、画面デザイン詳細、物理データ構造、API・ファイルの物理仕様 |

対象範囲：

- ログイン画面（SCR-004）からのログインと、Web API によるログイン（FR-002）
- ログイン状態の開始（Web API のログイン状態はログインから24時間有効、画面のログイン状態は無操作30分で解除）
- ログイン後の遷移（購入者は商品一覧 SCR-001、管理者は注文一覧 SCR-102。認証が必要な画面から誘導された場合は元の画面）
- ログアウト（FR-003）によるログイン状態の解除
- ログイン利用者情報照会（FR-004）
- 多重ログイン、認証エラー（未ログイン・ログアウト済・有効期間経過・無操作による解除）の扱い
- ログイン成功・失敗、ログアウトの監査ログ記録

対象外：

- 会員登録（UC-001）
- 管理者アカウントの作成（UC-013）
- 会員情報の変更、パスワード再設定、退会（FR-OUT-09）
- 認証失敗時のアカウントロック、ログイン試行回数制限（FR-OUT-11）
- ログインに関するメール通知（FR-OUT-08）
- 監査ログの照会機能（本リリースでは提供しない）

## 3. 目的・開始条件

### 3.1 Goal

会員登録済みの購入者、および管理者が、メールアドレスとパスワードで本人であることを示してログインし、利用者区分（購入者／管理者）に応じた機能を利用できる状態になる。利用後はログアウトして、使っていたログイン状態を解除する。

### 3.2 Trigger

来訪者がログインの操作を選択してログイン画面（SCR-004）を表示し、ログインを実行したとき。または、未ログインの来訪者が認証を必要とする画面を要求して SCR-004 へ誘導されたとき。または Web API でログインを要求したとき。ログアウトは、ログイン中の利用者が画面でログアウトの操作を選択したとき、または Web API でログアウトを要求したとき。

### 3.3 Precondition

| ID | 前提条件 | 満たさない場合の扱い |
|---|---|---|
| PRE-UC-002-001 | ログインする利用者（購入者または管理者）が利用者として登録済みである（購入者は UC-001 または UC-013、管理者は UC-013 で登録）。 | ログインは認証失敗となる（EX-04） |
| PRE-UC-002-002 | ログアウト（FR-003）・ログイン利用者情報照会（FR-004）は、有効なログイン状態の利用者が行う。 | 認証エラーとなる（EX-01） |
| PRE-UC-002-003 | MiniCommerce が稼働している（計画停止中でない）。 | 開始不可。処理中に障害が発生した場合は EX-06 |

## 4. 基本フロー

| Step | Actor / System | 操作・振る舞い | 結果・状態 |
|---|---|---|---|
| 1 | ACT-001 来訪者 | ログインの操作を選択する | ログイン画面（SCR-004）にメールアドレス・パスワードの入力項目が表示される |
| 2 | ACT-001 来訪者 | メールアドレスとパスワードを入力し、ログインを実行する（FR-002） | ログインが要求される |
| 3 | System | メールアドレス（前後空白除去後）・パスワードが入力されていることを確認する。メールアドレスは前後空白を除去し全体を英小文字にした値（正規化後の値）で照合する（BR-UC-002-001・BR-UC-002-002） | 入力不備は通知されない（未入力の場合は EX-03） |
| 4 | System | 正規化後のメールアドレスの利用者が存在し、入力されたパスワードが登録済みのパスワードと一致する場合に認証する（BR-UC-002-003） | 認証に成功する（一致しない場合は EX-04） |
| 5 | System | ログイン状態を開始する（Web API のログイン状態の有効期間はログインから24時間、画面のログイン状態は無操作30分で解除）。監査ログにログイン成功（対象利用者）を記録する | 利用者は ACT-002 購入者として認証済みとなる |
| 6 | System | Web API の場合は、開始したログイン状態を示す情報、その有効期限日時（ログインから24時間後）、ログインした利用者の利用者ID・メールアドレス・氏名・利用者区分（購入者）を応答する。画面は商品一覧（SCR-001）へ遷移し、氏名とログアウトの操作を表示する | 購入者向けの機能（UC-004〜UC-009）が利用できる |
| 7 | ACT-002 購入者 | ログイン利用者情報を照会する（FR-004） | 照会が要求される |
| 8 | System | 自分の利用者ID・メールアドレス・氏名・利用者区分を応答する | 状態は変化しない |
| 9 | ACT-002 購入者 | ログアウトの操作を選択する（FR-003） | ログアウトが要求される |
| 10 | System | その操作に用いたログイン状態を解除する。監査ログにログアウト（対象利用者）を記録する。Web API の場合はログアウトの完了を応答し、画面は商品一覧（SCR-001）へ遷移してログインの操作を表示する | 利用者は ACT-001 来訪者の状態に戻る。解除したログイン状態での以後の要求は、ログインが必要である旨の通知となる |

| 発生箇所 | Main Flow Step 3〜10 |

| 2 | System | 画面はエラー画面（SCR-901）を表示する | 利用者は時間をおいて再実行できる |

## 7. Postcondition

### 7.1 正常終了

- ログイン後：ログイン状態が開始されている。Web API のログイン状態は、現在時刻が有効期限日時（ログインから24時間後）より前の間だけ有効である（有効期限日時ちょうど以降は無効）。画面では、購入者は SCR-001、管理者は SCR-102（誘導された場合は元の画面）が表示されている。
- ログイン後：監査ログにログイン成功（対象利用者、結果＝成功）が1件記録されている。
- ログアウト後：その操作に用いたログイン状態は解除され、以後の要求はログインが必要である旨の通知となる。同じ利用者の他のログイン状態は有効なままである。画面は SCR-001 が未ログインの表示で表示されている。
- ログアウト後：監査ログにログアウト（対象利用者、結果＝成功）が1件記録されている。

### 7.2 失敗終了

- ログイン失敗時：ログイン状態にならない。利用者の内容は変化しない。
- 認証失敗（例外E-002-02）時：監査ログにログイン失敗（結果＝失敗）が1件記録されている。
- ログアウト失敗時：ログイン状態は操作前のままである。
- いずれの場合も、パスワード・メールアドレス・ログイン状態を示す情報・氏名はアプリケーションログ・監査ログに出力されない。

## 8. 業務ルール・制約

| ID | ルール・制約 | 適用箇所 | 関連Requirement ID | 備考 |
|---|---|---|---|---|
