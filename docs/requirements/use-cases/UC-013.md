## 1. 本書の目的と適用範囲



### 1.1 目的

運用者（システム運用担当）が、EC運営担当の作成した定義ファイル1件を1回の実行で投入し、利用者（管理者・購入者）・仕入先・商品分類・商品・在庫単位・クーポンを、定義ファイルと同じ件数・内容で登録する。違反が1件でもあれば何も登録せず違反内容を全件確認できること、既存データ（監査ログを除く）を削除してから投入する指定で検証環境を初期状態に戻せることを含む。


### 1.2 適用範囲

| 区分 | 内容 |
|---|---|
| Use Case ID | UC-013 |
| 対象ユースケース | 初期データを一括投入する |
| 対象リリース・範囲 | MiniCommerce 初期リリース |
| 本書で定義する | Goal、Actor、Trigger、Precondition、Flow、Postcondition、Business Rule、AC |
| 本書で定義しない | 実装方式、画面デザイン詳細、物理データ構造、API・ファイルの物理仕様 |

対象範囲：

- 定義ファイル1件の読込と、値域・一意性（定義ファイル内・既存データとの重複）・参照整合性の検証（FR-060）
- 業務キー（メールアドレス、仕入先コード、分類コード、商品コード、SKU、クーポンコード）によるデータ間の参照の指定
- 既存データ（監査ログを除く）を削除してから投入する指定：監査ログ以外の全データ（利用者・仕入先・商品分類・商品・商品分類所属・在庫単位・クーポン・カート・カート明細・注文・注文明細・配送先・決済記録・注文状態履歴）を削除してから投入する。定義ファイルに違反がある場合は削除も投入も行わない
- 投入結果（データ別の投入件数、違反内容の全件）の運用者への提示と、監査ログ（イベント種別 初期データ一括投入）の記録

対象外：

- Web画面・Web API からの投入（実行手段を設けない）
- 定義ファイルの作成（EC運営担当が本システム外で作成する）
- 注文・注文明細・配送先・決済記録・注文状態履歴・カートの投入（定義ファイルの対象外）
- 個別のマスタの画面・Web API による登録・更新・削除（FR-OUT-02）、入荷・在庫補充の登録（FR-OUT-03）
- 既存データの部分更新（既存データ（監査ログを除く）を削除してから投入する指定をしない場合は追加のみ。業務キー重複はエラー）
- 保存期間を過ぎたデータの削除（運用者が年1回、手順に従い別途実施）

## 3. 目的・開始条件



### 3.1 Goal

運用者（システム運用担当）が、EC運営担当の作成した定義ファイル1件を1回の実行で投入し、利用者（管理者・購入者）・仕入先・商品分類・商品・在庫単位・クーポンを、定義ファイルと同じ件数・内容で登録する。違反が1件でもあれば何も登録せず違反内容を全件確認できること、既存データ（監査ログを除く）を削除してから投入する指定で検証環境を初期状態に戻せることを含む。


### 3.2 Trigger

稼働開始前のマスタ登録、マスタの再投入、または検証環境を初期状態に戻すときに、運用者が定義ファイルを指定して初期データ一括投入を実行する。


### 3.3 Precondition

| ID | 前提条件 | 満たさない場合の扱い |
|---|---|---|
| PRE-UC-013-001 | 運用者が初期データ一括投入を実行できる権限を持つ（本システムの利用者の認証の対象外）。 | 開始不可（初期データ一括投入を実行できない） |
| PRE-UC-013-002 | システムが利用可能な状態である。 | 開始不可。投入中に障害が発生した場合は EX-05 |
| PRE-UC-013-003 | EC運営担当が作成した定義ファイルが、運用者が投入時に指定できる状態で用意されている。検証環境で用いる定義ファイルの個人情報は架空の値のみである。 | 定義ファイルが存在しない・読み込めない場合は EX-01 |

## 7. Postcondition



### 7.1 正常終了

- 定義ファイルの全データが登録され、データ別の件数が定義ファイルの件数と一致し、その件数が運用者に示されている。
- 投入した管理者・購入者は、定義ファイルに記載したメールアドレスとパスワードでログインできる。
- データ間の参照は、定義ファイルで業務キーにより指定したとおりに関連付けられている。
- 既存データ（監査ログを除く）を削除してから投入する指定をした場合は、監査ログ以外の既存データ（注文・カートを含む）が削除され、業務データは定義ファイルの内容のみとなっている。監査ログは削除されずに残っている。
- 監査ログに初期データ一括投入の実行（結果 成功、対象の利用者は値なし）の記録が1件追加されている。


### 7.2 失敗終了

- 業務データは実行前の状態のまま（1件も投入されず、既存データ（監査ログを除く）を削除してから投入する指定をした場合も削除されない）。
- 違反内容（データ名・行番号・項目・理由）が全件、運用者に示されている。
- 監査ログに初期データ一括投入の実行（結果 失敗）の記録が1件追加され、失敗したことが運用者に示されている。

## 9. Acceptance Criteria / 合否判定基準



### 9.1 AC-UC-013-001：定義ファイルを投入するとデータ別の投入件数が表示され件数が一致する
