## 1. 本書の目的と適用範囲



### 1.1 目的

運用者（システム運用担当）が、EC運営担当の作成した定義ファイル1件をコマンド1回で投入し、利用者（管理者・購入者）・仕入先・商品分類・商品・在庫単位・クーポンを、定義ファイルと同じ件数・内容で登録する。違反が1件でもあれば何も登録せず違反内容を全件確認できること、全削除オプションで検証環境を初期状態に戻せることを含む。


### 1.2 適用範囲

| 区分 | 内容 |
|---|---|
| Use Case ID | UC-013 |
| 対象ユースケース | 初期データを一括投入する |
| 対象リリース・範囲 | MiniCommerce 初期リリース |
| 本書で定義する | Goal、Actor、Trigger、Precondition、Flow、Postcondition、Business Rule、AC |
| 本書で定義しない | 新たな実装方式の決定。受領済みのAPI・画面条件は要求根拠として維持 |

対象範囲（原資料 In Scope）：

- 定義ファイル（JSON、UTF-8）1件の読込と、値域・一意性（定義ファイル内・既存データとの重複）・参照整合性の検証（FR-060）
- 業務キー（メールアドレス、仕入先コード、分類コード、商品コード、SKU、クーポンコード）による参照の解決と識別子（ID）の付与
- 利用者のパスワードのハッシュ化保存（NFR-SC-01）
- オプション「全削除して投入」（--reset）：監査ログ以外の全データ（利用者・仕入先・商品分類・商品・商品分類所属・在庫単位・クーポン・カート・カート明細・注文・注文明細・配送先・決済記録・注文状態履歴）を削除してから投入。定義ファイルに違反がある場合は削除も投入も行わない
- データ別の投入件数の標準出力、違反内容の全件出力、監査ログ（event_type=initial_data_load）の記録

対象外（原資料 Out of Scope）：

- Web画面・API からの投入（実行手段を設けない）
- 定義ファイルの作成（EC運営担当が本システム外で作成する）
- 注文・注文明細・配送先・決済記録・注文状態履歴・カートの投入（定義ファイルの対象外）
- 個別のマスタの画面・API による登録・更新・削除（FR-OUT-02）、入荷・在庫補充の登録（FR-OUT-03）
- 既存データの部分更新（全削除なしの場合は追加のみ。業務キー重複はエラー）
- 保存期間を過ぎたデータの削除（運用者が年1回、手順に従い別途実施）

## 3. 目的・開始条件



### 3.1 Goal

運用者（システム運用担当）が、EC運営担当の作成した定義ファイル1件をコマンド1回で投入し、利用者（管理者・購入者）・仕入先・商品分類・商品・在庫単位・クーポンを、定義ファイルと同じ件数・内容で登録する。違反が1件でもあれば何も登録せず違反内容を全件確認できること、全削除オプションで検証環境を初期状態に戻せることを含む。


### 3.2 Trigger

稼働開始前のマスタ登録、マスタの再投入、または検証環境を初期状態に戻すときに、運用者がサーバー上で投入コマンドを実行する。

## 7. Postcondition



### 7.1 正常終了

- 定義ファイルの全データが登録され、データ別の件数が定義ファイルの件数と一致し、標準出力に表示されている。
- 投入した管理者・購入者はメールアドレスとパスワードでログインでき、パスワードはソルト付き一方向ハッシュでのみ保存されている。
- データ間の参照は業務キーで解決され、識別子（ID）はシステムが付与している。
- --reset 指定時は、監査ログ以外の既存データ（注文・カートを含む）が削除され、業務データは定義ファイルの内容のみとなっている。監査ログは削除されずに残っている。
- 監査ログに event_type=initial_data_load、user_id=空、result=success の記録が1件追加されている。


### 7.2 失敗終了

- 業務データは実行前の状態のまま（1件も投入されず、--reset 指定時も削除されない）。
- 違反内容（データ名・行番号・項目・理由）が全件出力されている。
- 監査ログに result=failure の記録が1件追加され、終了コードは0以外である。
